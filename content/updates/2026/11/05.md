## Fixes

### Black video thumbnails

Two causes. The poster generator drew the frame the moment `seeked` fired on a detached video, so posts got solid black thumbnails, every post video on dev. It now waits for decoded frame data, rejects flat frames and tries later points in the clip, uploading no poster rather than a black one, and the clip's upload no longer waits for the poster to be made. Old black posters are detected once per device and skipped, so players fall back to the clip's own first frame. On Android the WebView painted its grey "big play" placeholder over any video without a poster, so a chrome client now returns a transparent default poster. (`7b7bf24`)

A backfill script finds videos with no poster, videos whose poster is solid black, and post, avatar and cover images with no `_thumb`, and makes the thumbnail the current client would. It stores it at the derived key through the R2 provider, so chat media stays in the private bucket, and upserts the Media row with the original's owner and visibility, never over a row someone else owns. It is a dry run by default, `--apply` refuses production unless `--allow-production`, and it was run on development. (`06c7f5c`) "Clear cached data" now also forgets which thumbnails were missing and which posters were blank, and re-fetches those posters with a cache-bypassing reload, so a fixed poster replaces the black copy the browser had cached for a year. On a browser with no IndexedDB it no longer reports "Couldn't clear cached data" when nothing was stored. (`1ebaf61`)

### Text fields ignored their limit

The fields accepted any length and only a counter said a post (2,000) or a comment (500) was too long. `MentionInput` now has a hard `maxChars`: keystrokes past the limit are refused, a paste is cut to what fits with a notice, and text an Android keyboard commits past it is trimmed once the word is finished, never mid-composition. The chat composer's own cap never ran, because it clamped a string while the field reports `{ text, mentions }`, and its counter read `.length` of that object. Both now count characters the way the server does. (`a58a55d`)

### Signed-out devices stayed connected

"Sign out" in Settings, Devices revoked the session for API requests at once, but the device's open realtime socket was only closed by a once-a-minute sweep, so it kept receiving messages for up to 60 seconds. Every sign-out path now publishes a sessions-revoked event over the Redis bus and each replica runs the sweep within 250 ms. Token rotations do not publish it. The device, told `session:revoked`, makes one signed-in request so the API's 401 path signs it out immediately. Device names now read Chrome, Firefox and Edge on iOS, Edge on Android, Samsung Internet and ChromeOS correctly instead of "Safari", "Chrome" or "Linux". (`8a079a2`)

### Comment notifications

Opening a post kept a 30-second cached copy whose comments missed anything written since, so a comment notification often showed the post without that comment. The copy now stays fresh for 5 seconds and a `#comment` link not in it refetches. The in-app toast and Recent Activity open the comment itself. Reply starts the box with a real @mention, and the "Replying to" line stays even if the name is deleted. (`46648a9`)

### Navigation and viewer

- **Logo and chrome:** Tapping MEETIFYY navigated to `/home` and restored the old scroll position, landing somewhere different each time. It now glides to the top and, in the app, runs the pull-to-refresh spinner while the newest page loads in place. A restored scroll position was read as a big downward swipe and hid the header and bottom nav mid-transition, the white flash under the status bar. For a moment after any navigation, scrolling now counts as the page settling. (`7f06e5b`)
- **Media viewer:** Swiping a photo or video to close rounds the corners of the visible picture and hides the video's bottom bar with the header. Replay no longer pauses itself, because the same tap also reached the delayed centre-tap play and pause. Dragging the timeline back from the end turns Replay back into Play, Share is gone from the viewers, and opening Forward no longer raises the keyboard while the sheet slides in. (`ed9dcaa`)
- **Paging arrows:** Touch-only devices swipe between items, so the arrows are hidden there. The trade-off is that a phone has no paging control while zoomed. (`c3b72b1`)

### Other fixes

- **Desktop search:** Community and Crew search reused the global search stylesheet, which hides its search row on wide screens, so desktop users had no input at all. The joined-communities grid no longer cuts off the outer cards, and cards highlight the whole card on hover instead of lifting with a blue border. (`a360852`)
- **CSP:** Presigned uploads go straight to `<account>.r2.cloudflarestorage.com`, but the report-only policy, which will be enforced next, only allowed `*.r2.dev`. Nothing breaks today, since the enforced policy still allows `https:`, and uploads will keep working once the stricter policy is switched on. (`387a294`)
- **Notification island:** After a swipe the next notification opened already expanded, because zero-length resets had not landed before the next animation. Every island value is now a motion value reset synchronously, rows move on the same spring as the island edge, and closing reverses the opening without rebounding. (`7076340`)
- **Island swipe:** Dragging a row inside a multi-row island cut it off at the island's clip edge and left the rows around the gap with square corners. While a row is swiped the clip comes off and every row eases to rounded corners. (`9605320`)
- **iOS plugins:** `Package.swift` listed only Capacitor itself, so an iOS build would compile with none of the plugins present. It now declares secure storage, app, network, push notifications and Sentry. (`bc2d0ba`)

## Improvements

### Notification island

The sonner instant-notification cards are replaced by one island at the top: a pill with the Meetifyy mark that expands into up to three stacked rows, newest sliding in on top. A store queues, groups same-chat messages into one row, dedupes and pauses timers on hover, press and backgrounding, and opening the chat clears its row. The shape animates as a `clip-path` on a fixed shell, with no per-frame layout. (`e0f7927`) A fourth notification no longer pushes the oldest out: anything past three waits in a queue capped at 12 and enters at the top as soon as a row leaves, so a burst of ten shows all ten, three at a time. Holds freeze the visible set while a finger is down. (`d37f450`) Toasts are now 14 px rounded boxes in the app's surface colours with a small tinted status tile, bottom-right on desktop and wide on phones. (`288a6b4`)

### Community ownership and requests

Owners can hand a community to another member (Members, then Make owner). The API checks the caller is the current owner and the target is an active, verified member, and still at the campus for a campus community. It moves ownership in one conditional transaction, and the old owner stays as moderator. Creating a Campus community without a verified college is refused instead of silently making it public. Clearing a description now clears it, names may use "&" with an inline reason when rejected, and the applicant is told when a join request is accepted or declined. Join-request events go only to the person they concern, not to everyone viewing the community. (`0f58b2c`)

### Logging out

Logging out puts a centred "Logging out" card with a spinner over the page, then ends the session and empties everything the account left on the device: query cache, IndexedDB feed, messages and drafts, service-worker caches, signed media URLs and this tab's session storage, with a 2.5-second cap. It then goes to the landing page or the login screen, preloads it, and lifts the cover only once it has painted. Back cannot return to the signed-in page. (`6cc0f41`)

### App

- **Page transitions:** The centre opening rounds all four corners of the closing page as it shrinks, and the slide rounds the moving page's two visible corners, flattening to square as it settles. The app is portrait-only: the activity is locked, iOS lists Portrait only, and video fullscreen no longer turns the screen. (`024ab32`)
- **Bottom sheets:** Moves are painted straight from `touchmove`, grabbing a sheet while it springs back continues from where it visibly is, and closing by drag leaves the sheet off screen while React removes it, which fixes the close flicker. (`8915a6d`)
- **Campus:** In idle time after sign-in, the Campus page's code is fetched and, for an unverified account, the join screen's hero image is decoded. Only code and that one picture are fetched, and the page's data is still requested only when Campus is visited. (`052529c`)

### Cards and pages

- **Communities:** From 769 px wide the card uses a 48 px icon and a smaller Join button, and the Join button sits beside the name with the member count and description below. (`ef445f3`, `935dc6b`)
- **Profile and covers:** The profile and community covers end in rounded bottom corners. A profile's bio and interests ease in when they arrive late instead of snapping the card taller. The user card beside a post keeps a 3:1 cover with a 64 px avatar on its edge. (`58e06f1`, `49cc157`, `3ef1859`)
- **Post detail:** The detailed post is one column with a single 0.75rem gap and no inner margins. The inline reply composer matches the 40 px comments below it. (`97fa310`, `5b39ce5`)
- **Lists:** Notification rows are tighter and the virtual list's size estimates follow, so scrolling does not jump. System notices in chats use smaller text and a slimmer pill. The left sidebar's active line glides between sections. (`0c25782`, `7434352`, `e80aa43`)

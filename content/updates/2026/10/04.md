## Fixes

### Site unscrollable after the launch shell

The launch shell locked scrolling with inline `overflow` styles on `html` and `body` while React mounted behind it. Pages and overlays that save an inline overflow to restore later saved the boot lock as the original value and wrote it back after the shell lifted, leaving the site unscrollable until a reload. The lock is now a class on `html`. `LandingPage` and `PublicNotFound` clear their overrides on unmount instead of restoring a captured value, and `LegalUpdateGate` uses the shared `useScrollLock`. CSP script hashes are updated for the edited inline script. (`8fcf5cf`)

### Keyboard review fixes

- The text-entry attribute, `--app-vh`, the virtualizer override and the keyboard-hidden collapse are installed-app only, so the website keeps the URL-bar collapse, pinch zoom and iOS single-tap keyboard.
- Text entry is evaluated on every pass, so the final resize of a closing keyboard can no longer leave it stuck on.
- The viewport baseline resets when no keyboard can be the cause (split screen, exited fullscreen video), and pinch zoom is not a keyboard.
- A new `meetifyy:text-entry-end` event makes system-bar sampling and inline video replay what they skipped.
- The keyboard-hidden collapse only applies when the text field has focus, not when a file picker button does.

(`88da85c`)

### UI fixes

- Messages: the square background behind the rounded box on desktop is removed.
- Saved: a larger title and a boxed card on large screens, like Communities.
- Notifications: clearer section labels with dividers.
- Profile: the academic catalogue is read synchronously from cache and the skeleton is held until it is ready, so the tag rows no longer re-balance late.
- Media viewer: the image transform is not reset while closing, which jumped it back to the centre before the fade.
- Chat (app): the composer clears the navigation bar and the details header clears the status bar.

(`7767b51`)

## Improvements

### Legal pages as static content

The four legal documents are now static content, copied verbatim from the published production versions, and render without an API call. The Legal section is removed from the admin panel and the backend admin API. Consent tracking and the acknowledgement gate are unchanged. In the installed app the legal routes are not bundled, and opening one hands off to the same path on the website in the system browser. Help & Support in the app gets an app top bar below the status bar and follows the dark theme. (`37f61b7`)

### Instagram on the web share sheet

On the website the Instagram tile copies the link, because Instagram has no web share URL. The app keeps its Story tile unchanged. (`d7879fc`)

### Composer and keyboard

Causes found on the device:

- Post media were sized in `vh`, which shrinks with the keyboard, so every image resized and the feed re-laid out. Media now use `--app-vh`, the keyboard-free viewport unit.
- The bottom nav and Instant Match button rode the shrunken viewport onto the keyboard for a few frames. In the app they now stay on the physical bottom edge in the same layout pass.
- The window virtualizer measured the shrunken window and mounted and unmounted rows as the keyboard opened. It now reports a steady height during text entry.
- The system-bar colour sampler forced style recalculation on every DOM change and resize, about 40 ms per tap. It caches the theme colour and pauses during text entry.
- Inline video paused and resumed when the keyboard shrank the viewport.

The composer now expands with a smooth grid-row transition and requests the keyboard only after the expand finishes. Android Back, which hides the keyboard without blurring, collapses an empty composer. Focus never scrolls the page. (`bf3cf6e`)

## Fixes

- **Blank Notifications:** The virtualised list could render zero rows because its scroll element ref attached after the list measured. The page now hands the list its scroller through state and falls back to window virtualisation on the website. Loading shows a spinner in place of skeletons, and the first page is prefetched in idle time with the same query options. (`26d1fc8`)
- **Status bar flicker:** On Profile the icon rule ignored the page's hint, so status icons flipped dark and white each time the header hid. Going from Profile to Home, the strip kept Profile's see-through colour, and on Home's header return it read the pale fallback instead of the gradient and slid back pale. Leaving Search with the keyboard up skipped the next page's sample, and closing the media viewer kept its black until the fade ended. (`bc614be`, `158dc97`)
- **Comment composer:** The optimistic comment showed at once but the composer kept the text until the server answered. It clears immediately and restores the draft if posting fails. The post is no longer refetched after every comment, and `addComment` runs its four independent reads in parallel and writes the comment and count bump as one. (`0315a43`)
- **Auth status bar:** `AuthShell` forced light status icons, which vanished on the white signup page. They are requested only over the phone login header image. (`5c0b2ee`)
- **Community page:** The back button is the rounded square Profile uses. The details sheet's status icons follow the theme. A freshly uploaded avatar or cover could load before a reset ran and leave the shimmer on until the community was reopened, so loading state is keyed by URL. (`358215a`)
- **Theme toggle:** Presses under 150 ms apart are ignored. (`4a1331f`)

## Improvements

### Keyboard

The Android WebView is no longer resized for the soft keyboard. The shell publishes one `meetifyy:ime` event per transition and zeroes the IME inset it passes to the WebView, so the page never gets a resize or a whole-page restyle while the keyboard moves. Docks rise with a transform on the keyboard's own curve and stand on its top edge. (`d65d479`)

### Communities

- **Avatars:** One shape for every community picture, `--community-avatar-radius` (28%), across the directory, hero, campus page, search, post badges, sidebars, share sheet, chat previews, reply quotes, notifications and croppers. People stay circular, and a static test keeps the two apart. The Communities page gets a narrower centred list with a larger avatar and the member count beside the name. A community post whose picture fails to load shows the community's letter. (`58d309e`)
- **Card grid:** Communities, Campus Communities and community search become a grid of 21rem cards, packed from the left, one per row on phones. Campus discovery uses the same card. (`1a4057a`)

### Cover editor

The cover editor is a drag-to-close bottom sheet, with a miniature profile preview and drafts until Save. It has eight CSS-only patterns beside the six gradients. A profile stores the design's CSS, not an id, so removing a design never breaks a profile using it. The CSS is sanitised on write and not painted on read, so a cover cannot make viewers fetch a URL. For a photo, pick, crop and the cover shows the local image at once while it uploads in the background with a progress bar. Unsupported or oversized files are refused, a newer choice cancels an upload in flight, and a failure restores the previous cover. (`689c452`)

### Sharing and forwarding

Forward opens the share sheet in a forward mode, replacing the separate modal in chat and the media viewer. Each recipient still gets a client id derived from one operation id per opening, so a retry is recognised by the server and only goes to the chats that failed. The subject preview card is removed from every share dialog. (`818a890`)

### Smaller changes

- The post header is quieter, with the handle and time in subtitle colour and a new two-line menu icon. (`3378d10`)
- The profile loading skeleton is an outline rather than a copy of the page. (`0cbf4fc`)
- Every auth input has a 1 px border. (`be839e9`)
- The installed app shows no Cookie Policy link, since it sets no cookies. (`337bdd5`)

### Performance

- **Composer:** Animating `grid-template-rows` re-laid out the composer and the whole feed on every frame. The size now changes in one step and `useExpandFlip` draws the in-between frames with `clip-path` and a transform, both compositor-only. (`d8a2028`)
- **Theme switch:** The visible animation is unchanged. Nothing is written to `<html>` before the capture, the bars switch icons as the circle reaches them, and strip colours are written to their own rules so a sample no longer restyles the page. A second press reverses it. (`6f3fd6d`)
- **Drawer:** The scroll lock walked every element with `getComputedStyle` on the frame the drawer started opening. It now follows one slide later, the scrim drops its blur on touch devices, and the drawer gets layout and paint containment. (`6c6cf4d`)
- **Auth pages:** The landing page now loads the login and signup chunks and background once idle, and at once on hover, touch or focus of an auth link. (`b0ad9df`)

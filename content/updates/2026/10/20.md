## Fixes

### Audit findings

Three independent audit reports were checked against the code, and this applies the findings that held up.

- **Messaging:** History, mark-as-read, reactions, delete-for-me and system messages now require an active participant, and suspended or deleted accounts can no longer send.
- **Posts and communities:** Every single-post route and search enforces community access, list cursors no longer skip a row per page, block checks are added, and member lists and presence respect privacy.
- **Uploads:** Support attachments are private with signed admin links, file type comes from the validated content type, and users cannot attach or upload into other people's or reserved media.
- **Auth:** `@VerifiedOnly` now works on HTTP, banned and deleted accounts are rejected, cookie users get per-user rate limits, reserved usernames are blocked at signup, and a Supabase outage no longer logs users out. Password reset revokes every session through a new recovery-token route.
- **Admin:** Force-logout and delete now revoke sessions.
- **Rate limits:** New limits cover posting, commenting, community creation and presigned uploads. No migrations.

(`180e251`)

### Private support attachments in emails

Support attachments are private, so the `/api/media/support/<key>` links in the "request received" email 404 for everyone. The email goes to the person who uploaded the files, so it lists file names and sizes with no link. A signed URL was rejected because anyone the email is forwarded to could open the file until it expired. Admins still open attachments through short-lived signed URLs on the ticket page. A new spec pins that no link is emitted for either key shape. (`2c890b2`)

### Repeated reloads and asset caching

A stale chunk after a deploy could cause repeated reloads, and blanket immutable caching on asset responses made it worse. Stale-chunk reload protection is preserved across startup, immutable caching is no longer applied to every asset, and reload caching is validated and handles blocked session storage. These landed through a merged pull request, and each commit exists on both branches. (`2c19f4a`, `61ef5ab`, `5b78a60`, `f36f15c`, `da6fd70`, `e47ab41`, `0658cca`)

### Home scroll snapping

Going back rebuilt the virtualised feed from estimates, so rows measured above the restored position nudged the page. The feed now remembers each row's measured height per layout width and seeds the next mount with it. The restore used to re-run whenever loading flipped, so after a pull-to-refresh it threw the page to a stale position. It now restores once before paint and flushes the pending save on leave. (`1679289`)

### UI fixes

- **Community leave:** The mute dialog freezes the page behind it, and leaving a community asks first in a matching dialog. In the installed app the menu button was painted over by the fixed header and now lives in the header's right slot. Instant notification cards are centred at every width with a blue-tinted surface. (`6d5d18f`)
- **Comment header:** The `@username` and time were smaller than the name and the row centred two typefaces' boxes, so the small text sat off the baseline. They are the same size and share a text baseline. (`013c862`)

## Improvements

- **Verification prompt:** An unverified user who hits a create or send action gets the "verify with a live selfie" dialog instead of a generic error. The API error carries a `VERIFICATION_REQUIRED` code and one shared handler opens the dialog, with a fallback for the old plain-text 403. (`8c9be4b`)
- **Password reset:** The reset-password page makes a single call to a new finalize route, which signs out every session and sends the "password changed" email, and it tells the user if that fails. The admin ticket page links attachments through short-lived signed URLs. (`8c9be4b`)
- **College picker:** It is left-aligned and uses the full width of the box on large screens, and the college-email step stays centred. (`558ffa8`)

### Performance

"Your communities" found each community's last activity with a `GROUP BY ... MAX` over every post of every community the viewer is in, which grew with the posts in those communities instead of with how many were joined. It now looks up the newest live post per community through the existing index. Results are identical, checked against the development data. (`29c4620`)

## Build & Tooling

`npm audit` reported criticals in `proxy-addr` (IP spoofing through subnet matching) and `handlebars`, plus highs in `sharp`, `compression`, `undici`, `engine.io` and `brace-expansion`. `npm audit fix` was applied without `--force`, with overrides for `proxy-addr` and `undici`, the `multer` override bumped past its vulnerable range, and the `sharp` install-script allowance updated to 0.35.5. Root and admin-frontend are now clean. `nodemailer`, a major bump, and dev-only jest tooling are left for a separate change. (`1e97a4b`)

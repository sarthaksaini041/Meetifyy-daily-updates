## Fixes

### API

- **Search 500:** Every branch of the tier `CASE` in the people and community searches was a bound parameter, so Postgres typed the `CASE` as text and adding the personal score failed (42883). It was production's first Sentry issue after the release: `GET /api/search` returned 500. Each tier is now cast `::int`, a spec asserts every branch carries the cast, and the fixed queries were run against the dev database. (`ad3a16c`)
- **New posts hidden by a stale ranking:** The ranked Home feed caches its order in Redis and reuses it for any page-1 request within 2 minutes, renewing it each time. An order built before a post existed could not include it, so opening Home before posting hid the new post for as long as refetches kept coming. Rankings now record when they were built and are rebuilt when a post has been created since. (`58d1e91`)
- **Long posts failed with a 500:** Posts were allowed 5,000 characters into a 2,000-wide column. Comments are now capped at 500 and posts at 2,000, enforced by the API with a clear 400 and counted in code points as Postgres counts them, so an emoji is one character. The comment bar shows "N / 500" from 400 characters, and the post composer has a ring that fills and blocks Post past the limit. (`8d5ba14`)
- **Empty gallery:** Opening the details of a user you cannot message has no conversation row, so the gallery threw "Not a member" and showed "Try again". It now returns an empty page. The DM header menu offers only "View profile" in that case. (`efc42a5`, `3f47dcc`)
- **`start:dev`:** The Prisma CLI only loaded `backend/.env`, which no longer exists since development values moved to `.env.development`. Prisma is run through Node with `--env-file`, using the same precedence as the API. (`2ac0c96`)

### Android app

- **Voice messages:** The manifest never declared `RECORD_AUDIO`, so `getUserMedia` was refused instantly and every recording showed "Microphone access denied". `RECORD_AUDIO` and `MODIFY_AUDIO_SETTINGS` are now declared. Installed apps need the new APK. (`1484da8`)
- **Signup and legal links:** Terms and Privacy links loaded the site into the same WebView, which reloaded it and lost everything typed. Links now open in the system browser. If Android kills the app meanwhile, a 30-minute, single-use resume record restores the step and fields, and never stores the password, code or tokens. (`32d37f5`)
- **Dropdowns and keyboard:** Tapping a dropdown while typing took focus from the field, so the keyboard dropped and the menu snapped under a resized viewport. The first attempt kept the keyboard up and returned focus on close, and auth screens no longer re-centre when the keyboard moves. (`8868895`) Later the same day that approach was replaced: opening a dropdown over a raised keyboard placed it above the trigger and it dropped when the keyboard left, so the selects now blur the field, wait for the keyboard to finish closing (two settled frames, 450 ms cap) and then measure and open once. (`fb7d481`)
- **Status bar during media drag:** Dragging the chat media viewer down faded its backdrop, and the sampler looked through it to the blue document gradient and painted the status bar blue for the whole drag. The viewer is ignored by the sampler once the backdrop starts to fade. (`a417917`)
- **"Complete your profile" returning:** "Later" was remembered in `sessionStorage` and the server snooze only held for the same session id, so reopening asked again. It is stored in `localStorage` with a timestamp per account and hidden for 10 days on that browser. (`0795fe9`)
- **Drawer followers and following:** They went to a single history entry, so Back left the profile entirely. They now open the profile and then the list as a second entry, but the list push was batched with the profile push and the close cross did nothing, so it now runs in its own task. (`1c91a0e`, `15cc331`)
- **Home tab bounce:** Tapping a tab already in history jumped back by a delta computed from a stale page stack after a sign-in redirect or reload, landing on Crew instead of Home. The tracker now checks where the jump landed and navigates directly if it missed. (`b54e7974`)
- **Notice above nav bar:** A "can't message" notice filled the bottom bar including Android's navigation padding, so its text sat partly behind that bar. (`e25fe75`)
- **Fonts:** Changa, used only for the profile name and counters, loaded when Profile first rendered, so the text visibly swapped. It now loads once idle after launch. (`e24c1de`)

### Web and app

- **Media viewer:** The first open showed a lazy-load fallback and a scrim, then the viewer started from transparent, so the screen went dark, clear, then dark. The viewer chunk is fetched while idle and rendered directly. It also opens on the thumbnail already on screen, and on the app the scroll lock now clips only the root, which stopped the feed jumping to the top on every open. (`754da8f`, `a38eac2`)
- **Older chat messages:** Loading older messages added the same height the browser's scroll anchoring had already kept, so the chat overshot and snapped to the bottom. It now restores only the difference, correct with anchoring on or off. (`1eec156`)
- **Cookie banner:** The banner covered Save and Later on the profile prompt on a 667 px phone. It hides while the prompt is open. (`d6f79fd`)
- **Emoji picker:** Wheeling past either end of the list scrolled the page behind it, because the list lives in emoji-mart's shadow DOM. A native wheel listener swallows the event at the ends. (`ffd1a0f`)
- **Community header:** The header faded into a solid surface. It now blurs the cover like Profile, keeps its own pinned cover copy, and shows the community name and member count as the title scrolls away. (`04409ac`, `46fda4f`)
- **Sidebar communities:** The list was fetched on the tap, so the box opened to the last row's height and then jumped. It is fetched once the first screen is up. (`ebb133d`)

## Improvements

### Push notifications

- **API:** A `PushDevice` table and two notification types, added by an additive migration. Devices belong to the signed-in user and their login, and every sign-out or session revoke deletes them. Each notification is written first, then delivered on a BullMQ push queue with dedupe, retries and dead-token cleanup, so a provider outage never fails the action. It covers messages (no text on the lock screen), likes, comments, replies, mentions, follows, activities and communities. (`0e25115`)
- **Clients:** The website subscribes through the existing service worker, and a tap opens only a validated in-app route. The Android app registers with FCM with four channels, and taps are routed through `DeepLinkNavigator`, including cold starts. Settings gets a push panel with OS permission and per-category switches. Firebase config is per build type and git-ignored, and builds without it work. (`74c1f3f`)

### Verification by selfie or ID

Verification now takes one live camera capture, chosen by the user: a selfie or a photo of a government ID. The app has no file picker for it. The server re-encodes each capture with `sharp`, without EXIF, stores it under a key only the capture endpoint writes, and requires it fresh (30 minutes), unused and the right kind. A migration adds `VerificationRequest.method`. Presigned uploads into `verification/` are refused, and the legacy two-document request is kept, now DTO-validated, for installed apps that still send it. (`6ef4130`)

### Notifications and emails

- Once signed in, the app asks for notification permission a single time per device, only when push is available, the permission is undecided and the account has not turned it on. Accepting turns push on and registers the device. (`49b8a61`)
- Sign-in and password-changed emails showed the server's UTC time with no zone label. The login request and the password-changed event now carry the device's IANA timezone, and the email prints the time in that zone with its abbreviation, falling back to Indian time. Deploy the backend first, because the API rejects unknown fields. (`896d94e`)

### Profile and comments

- The profile showed a "College" tag for everyone, because `getCollegeName` falls back to that word. The tag now needs a verified college email, and Settings, Interests gets a "Show college and course" switch stored as `UserSettings.showCollegeOnProfile` through an additive migration. The server still returns college and course, and the switch hides them in the UI only. (`159da18`) The migration was renumbered 22 because migrations 20 and 21 had landed on development while it was numbered 19, so it sorted before two already-applied ones. It had not been applied anywhere, and the SQL is unchanged. (`954d3a3`)
- Comments are laid out to match the post above: no "Comments 53" header, a display name, a muted truncating `@username` and the time on one line, with a 40 px avatar and 32 px for replies. Post text lines up with the avatar edge, and the phone notifications page no longer scrolls for a short list. (`5817fc1`, `a034ffb`)

### Dev and production apps side by side

Debug APKs use their own app ID `app.meetifyy.dev`, labelled "DEV APP", so both apps can be on one phone. They are signed with different keys, so one could never replace the other. `app-links.json` lets each host name its own package, so dev links open DEV APP. (`0e31684`)

### UI polish

- **Communities:** Cards sit side by side in a fluid grid (at least 16rem each), community lists sit directly on the page instead of inside one more box, and posts from a community drop the small community icon on the avatar. (`707d590`, `abba0d3`, `c919414`)
- **Campus:** The college picker fills the phone screen, with calmer states, a plain white page on phones only, and a centred layout on desktop. The suggested students keep their order for the session. (`b84f120`, `17d7bd2`, `861e8e7`, `775b824`, `b327eba`)
- **Desktop modals and press:** Followers and Following and the Edit Cover sheet are roomier from 769 px up. The Create Activity button eases into a held press state and ignores repeat taps within 700 ms. (`13d8c2a`)
- **Bottom nav:** Icons grow from 26 to 28 px together with the profile avatar. (`0cc1e3f`)
- **Instagram stories:** The share sheet clears its picks when it closes. Story generation loads in parallel, caches bytes and the last three finished cards, and the card is 1200 px wide instead of 1500. Profile stories drop the interest tags. (`c1489bf`)

### Performance

- **After the first screen:** Opening the app fired 11 to 16 requests in the same second, and on the single half-CPU production API the feed and messages being looked at waited behind them (median 113 ms rose to 418 ms in those bursts). The unread count, trending hashtags and online friends now start once the first screen is up. (`c427322`)
- **Chat history:** A page of history ran four sequential stages, including reading the same conversation row twice. It is read once, in the same `Promise.all` as the participant lookups. (`955a5ca`)
- **Creating a community:** Six sequential round trips (seven for campus) become four, with the three reads together and cache invalidation in one call. A new spec counts the round trips. (`50b62e0`)
- **Query cache:** The default `staleTime` goes from 30 s to 5 min, so switching screens reuses cached data. The app no longer refetches every query on resume. (`b327eba`)

## Documentation

The privacy policy now says verification takes one camera photo, a selfie or a government-issued ID, that it cannot be uploaded from files, and that it is re-processed to remove location and device data. A migration publishes it as the next version silently, without an acknowledgement. The same change exists on two branches, and the two branches are merged. (`a35c227`, `a053a3c`, `431d897`)

## Build & Tooling

- **Env files:** Local development values live in `.env.development` and hold only hosted-dev values, with machine-only overrides in a git-ignored `backend/.env.local`. `FEATURE_FIRST_YEAR_ISOLATION` is removed from the example env files. (`3dd9f64`)
- **Release Sentry credentials:** `npm run mobile:apk -- release` loads the Sentry token, org and Android project from a git-ignored local file, so source maps upload without exporting them by hand. A file naming the dev org is refused so production maps can never land there. (`b4c6e5d`)

## Testing

The notifications cache tests never unmounted their rendered hooks, and on a loaded CI runner a hook could refetch after the next test had reset its mock, which failed a test and blocked the production deploy. `afterEach` now calls `cleanup()` first. (`1c152b3`)

## Fixes

### Security

- **Forwarding private messages:** forwarding looked the source message up by id alone, so anyone holding a message id could copy a private message into their own chat. The source must now be readable by the caller. (`996c4f7`)
- **Overwriting thumbnails:** any signed-in user could presign another user's `<key>_thumb.webp` and replace their feed thumbnail. A variant can now only be written by the owner of its original. The presign also returns the headers it signed, to be sent verbatim, and thumbnails are stored at their derived key so the UI finds them. (`dab188e`)
- **Tokens in logs and backups (Android):** debug builds logged secure-storage results, including the refresh token, to logcat. Logging is off, and Auto Backup and device transfer now exclude the credential file. (`ccb8f94`)

### Sessions and sign-in

- **Lost refresh-token rotation:** if the app was killed after the server rotated a refresh token but before the app stored the new one, the next launch presented the old token, which was treated as theft and signed the user out. The previous token is now accepted once, only if its successor was never used, rotated or revoked and is under 60 seconds old. The unused successor is revoked and a new one issued, and rotation is atomic. A session's first use is now stamped, which also keeps "last active" on the device list honest. (`89f10a5`)
- **Sign-out:** logout signs the tab out immediately and resets the query cache itself, so pages still on screen no longer refetch against a session that is ending. A newer session supersedes a sign-out still finishing, and post-login redirects work again. (`0708b28`)

### Messages and media

- **Stale conversation lists:** the list cache was written under `v2` keys but all three evictors used `v1` keys, so sends, blocks and account deletions left lists stale for the full TTL. Writer and evictors now share one key builder and delete the first pages directly instead of scanning. (`c5f9b71`)
- **Media viewer:** each open of the viewer has its own state, so a Forward or report flow from the last item no longer carries into the next. Reports target the message or post, never the URL, and remember what was already reported. Touch gestures, focus handling and closing on route change are tightened. (`20aa8ab`)

### Admin

The review screen showed "No ID card" both when nothing was uploaded and when signing a link to an uploaded document failed. The two cases now look different, and a purged request, whose documents the retention sweep removed, has nothing to sign. (`ef712a2`)

### Interface

- **Communities:** an empty campus ("start one") and a search with no matches ("search differently") now say different things, and the directory and create-community modal are restyled. (`e74a5ab`)
- **Notifications:** the swipe-to-dismiss card stays fully opaque while dragged. (`373db16`)
- **Android splash:** only the splash background fades, over 150 ms, because fading the whole view left a half-transparent logo over the feed. (`ccb8f94`)

## Improvements

### Chat gallery, forwarding and muting

- A new endpoint pages a conversation's shared photos and videos from the database, newest first, with the same active-member gate and read window as history. The gallery no longer depends on how much history the client has loaded. (`996c4f7`)
- The chat gallery uses it, with a layout sized to the panel. One forward recipient list, searchable across every conversation, is shared by the chat and the media viewer. Muting now asks first, since it silences every notification from the chat. Clearing a chat refreshes its gallery. (`d283530`)

### Comments and following

- Comments show two levels of replies, Instagram-style, while the server keeps the real reply tree, and a reply still notifies the person it answers. Replies are written in a single composer that shows the reply target as a tag, and wide screens get the composer under the post. (`da1f17b`)
- Unfollowing and blocking ask first, and the block dialog says that a block is mutual, not a mute. The follow button trusts the server's `isFollowing`, and the profile heals stale follow state. (`dc15088`)

### Press feedback and toasts

One delegated listener gives every control press feedback, replacing the global `:active` scale rule. Toasts sit below the status bar on both the website and the app. (`de96dca`)

### Faster startup and navigation

- **One round trip on a cold start:** the session refresh can now carry the profile, so a cold start no longer needs a separate profile request. Older apps ignore the new field. (`43fed42`)
- **Opens on your account:** the installed app opens on the saved account and the first Home feed page at once and verifies behind it. The access token is kept encrypted with a Keystore key and reused at launch when it has more than 2 minutes left, so launches within the hour no longer rotate tokens. The launch renewal also waits until the app is visible. (`815f31f`)
- **Tabs:** a tab's route loads on hover or press, and unvisited tabs load while the browser is idle. (`2d105cd`)
- **Smaller bundle:** the report modal, image compressor and auth client load only when used, and the app's entry chunk went from 550,898 to 453,897 bytes. (`faf8141`)
- **Comment replies:** the reply query is scoped by post, so it uses an existing index instead of scanning the Comment table at every depth. (`d0d7a12`)

### Media and rendering performance

- Feed video tiles show the uploaded poster, grid tiles no longer render a video as an image, and avatars up to 48 px use the 160 px thumbnail. A missing thumbnail is remembered for a day, recorded only after the original loads. (`1898522`)
- Invisible blurs on phones and per-message layers are removed, which cut GPU frame time on the bottom nav from about 8–9 ms to 6 ms on a mid-range phone. The users map keeps its identity unless a user changes, so a new message no longer re-renders every post and bubble. (`05f5d5e`)

### App lifecycle

The app now refreshes data on resume, except for infinite lists. After 30 seconds in the background it disconnects the socket and presence heartbeat, then reconnects and re-syncs on return. A socket that ran out of reconnect attempts is revived on resume or when the device comes back online. (`5e69c02`)

## Documentation

- Added a performance audit and an optimisation record, with measurements on a mid-range device. The operations guide now says both storage buckets' CORS policies must include the app origin, with a preflight check. (`ec6296f`)

## Fixes

### Security

- **Forwarding private messages:** Forwarding looked the source message up by id alone, so anyone holding a message id could copy a private message into their own chat. The source must now be readable by the caller. (`996c4f7`)
- **Thumbnail takeover:** Any signed-in user could presign another user's `<key>_thumb.webp` and replace their feed thumbnail, taking over the Media row through the upsert. A variant may now only be written by the owner of its original, over a variant row they own. It was inert only because direct uploads all failed at the time. The pass-through fallback also stores a thumbnail at its derived key, and the presign returns the headers it signed. (`dab188e`)
- **Lost refresh-token rotation:** A process killed between the server rotating a refresh token and the app storing the successor presented the old token on its next launch, which was treated as theft and signed the user out. Following RFC 9700 practice, the previous token is accepted again only if its successor was never rotated, revoked or used, and is under 60 seconds old. The unused successor is revoked and a new one minted, so an attacker inside the window gains a session that is revoked as soon as the real app returns. Rotation is now atomic. (`89f10a5`)
- **Credentials in logs and backups:** Debug builds logged secure-storage results, including the refresh token, to logcat. Logging is off. Auto Backup and device transfer now exclude the credential file, using both `fullBackupContent` and `dataExtractionRules` because each Android version reads only one. (`ccb8f94`)

### Other fixes

- **Conversation list cache:** Lists are cached under `user:conversations:v2:...` but all three evictors used v1 keys, so sends, blocks and account deletions left lists stale for the full TTL. Writer and evictors now share one key builder, and eviction is a direct `DEL` of the first pages clients refetch rather than a `SCAN`. (`c5f9b71`)
- **Admin verification review:** The screen showed "No ID card" both when nothing was uploaded and when signing a link failed. Each document is now `{ url, signError }`, signed for five minutes, and the two cases render differently. (`ef712a2`)
- **Sign out:** Logout signs the tab out synchronously and resets the query cache itself. The header cleared the cache first, which made mounted signed-in pages refetch against an ending session. (`0708b28`)
- **Resume and background:** `refetchOnWindowFocus` was off on the premise that a WebView fires no focus event. It fires `visibilitychange`, and the planned resume hook never existed, so nothing refreshed on resume. It is on now, except for infinite lists. After 30 seconds hidden the app disconnects its socket and presence heartbeat, and reconnects and re-syncs on return. (`5e69c02`)
- **Media viewer:** State is kept per open, so a Forward sheet or report flow from the last item does not survive into the next. Reporting targets the message or post, never the URL, and remembers what was already reported. (`20aa8ab`)
- **Notification card:** The swipe-to-dismiss card stays fully opaque, instead of fading as if it were already leaving. (`373db16`)
- **Campus communities:** An empty campus and a search with no matches now say different things. (`e74a5ab`)

## Improvements

### Messaging

- `GET /api/messages/:id/media` pages a conversation's shared photos and videos from the database, newest first, with the same active-member gate and read window as history, so the gallery no longer depends on how much history the client has loaded. (`996c4f7`)
- The chat gallery pages from that endpoint with a layout sized to the panel. One forward recipient list, searchable across every conversation, serves the in-chat sheet and the media viewer. Muting asks first, since it silences every notification from the chat. Clearing a chat invalidates its gallery. (`d283530`)

### Posts and profiles

- Comments render two levels deep, Instagram-style, while the server keeps the real reply tree and a reply still notifies the person it answers. Replies are written in one `ReplyDock` composer that shows the reply target as a tag. Feed videos respect the playback registry. (`da1f17b`)
- Unfollowing and blocking ask first, and the block dialog says it is mutual, not a mute. `FollowButton` treats a boolean `initialFollowing` as authoritative. (`dc15088`)
- One delegated listener provides press feedback for every control, replacing the global `:active` scale rule. Toasts sit below the status bar. (`de96dca`)

### Faster starts

- **Local-first boot:** With a Keystore refresh token and a saved profile, the app opens on that account at once and verifies behind it. A refusal tears everything down, and offline keeps the cached account. The first Home feed page is saved and restored before the first render, scoped to the user. The access token is kept beside the refresh token with its expiry, using AES-GCM under a Keystore key, and used at launch with more than two minutes left. (`815f31f`)
- **Refresh with profile:** `POST /api/auth/session/refresh` with `includeProfile: true` loads the profile concurrently and returns it only once the refresh succeeded, so a cold start is one round trip. Older apps ignore the field. (`43fed42`)
- **Splash hand-off:** Only the splash background fades, over 150 ms, because fading the whole view left a half-transparent logo over the feed. (`ccb8f94`)

## Findings

### Performance audit

`PERFORMANCE_AUDIT.md` and `PERFORMANCE_OPTIMIZATION.md` record the findings, measurements on a mid-range device, fixes and what was decided against. (`ec6296f`) Highlights of the fixes:

- **Tab routes:** Bottom nav and sidebar share a prefetch: a tab's route chunk loads on hover or press-start, and unvisited tabs load while the browser is idle. (`2d105cd`)
- **Comment replies:** `parentId` has no index, so every depth level scanned the Comment table. Scoping the query by `postId` uses the existing `(postId, createdAt)` index. (`d0d7a12`)
- **Bundle:** The report modal (100 KB), the image compressor (53 KB) and the auth client load on use. The app entry chunk goes from 550,898 to 453,897 bytes. The website build is unchanged. (`faf8141`)
- **Media:** Posters and thumbnails come first, a 404 thumbnail is remembered for a day, grid tiles no longer render a video as an `<img>` of the MP4, and avatars up to 48 px use the 160 px thumbnail. (`1898522`)
- **Rendering:** The bottom nav's `backdrop-filter` over an opaque background is removed (GPU p50 8 to 9 ms down to 6 ms on a mid-range phone, from a `gfxinfo` A/B). Phones drop blurs that blurred their own card, and the users map keeps its identity unless a user changes, so a message no longer re-renders every post body and chat bubble. (`05f5d5e`)

## Documentation

R2 setup notes now require both buckets' CORS policies to include the installed app's origin, `https://localhost`, and add the dev origins and a preflight check. (`ec6296f`)

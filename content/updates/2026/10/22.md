## Improvements

### Messages that land

- **Outbox:** Every send is recorded in an IndexedDB outbox before it goes out and cleared once confirmed, so a send cut off by the network or a killed app is resent on the next connect, in order per chat, with the same client id the server dedupes. Retries back off to 5 minutes and stop after 8 tries or a day. Refusals are never retried, and entries belong to one account and are wiped at sign-out. "Not delivered" offers tap-to-retry, and queued messages show Sending. (`730487e`)
- **One send path:** The chat screen no longer emits on the socket itself. Every message goes through the stored outbox, which tries the socket, then REST. It wakes on reconnect, coming online and resume, goes REST-first for a minute after an ack timeout, and puts a 45 s watchdog on each send. A message that gave up no longer strands those behind it. (`27492f5`)
- **Refusal codes:** A failed `message:send` ack carries a code: `REJECTED` for a refusal that will never succeed (blocked, closed chat, not a member, invalid payload), `RATE_LIMITED`, or `ERROR` for anything transient. The outbox retries only the last two, and older builds ignore the field. (`a443676`)
- **Duplicates refused by the database:** `(senderId, clientMessageId)` is a unique index, so two copies of a send that get past the lock together can no longer both be stored. Production held no duplicate pairs. The losing insert is answered by sending once more, which finds the winning row and returns it as already delivered. (`6bb60de`)
- **Retries of delivered messages:** A retry of a message that already landed returns it before any block, membership or closed-chat check, so the sender is not told "Not delivered". (`7042832`)

### Idempotent writes and paged catch-up

- **Idempotency:** Writes carrying an `Idempotency-Key` run once per user and route. A repeat gets the first result, a different body is refused, and failures free the key. DM and group REST sends dedupe on `clientMessageId`, and all send paths lock per client id. (`df86666`)
- **Catch-up:** Reconnect catch-up pages by `(createdAt, id)` with `hasMore` and a server-clock `syncedAt`, re-reads 10 seconds, and honours cleared, left and Instant Match chats. The client pages until done, keeps the server's sync point and never advances on error. (`df86666`, `9d69271`)
- **Opt-in per route:** Only the nine create routes that clients key per submission accept a key, with results kept for an hour and capped at 32 KB. Redis runs `noeviction`, so open keys on every write would let one account fill it. Message dedupe matches the unique index's scope and refuses a client id reused in another chat. Catch-up gives each chat its own time range so the index bounds the scan. (`e2f62a4`, `bfe4697`)

### Offline and drafts

- **Offline everywhere:** One network signal drives TanStack and a single offline and back-online notice. Creates are refused offline with the draft kept, toggles are refused rather than flipped and undone, and a request lost mid-send keeps the text to retry. Screens keep cached data through failed refreshes. Chats open from the device offline. The installed app reads connectivity from Android itself, and a Wi-Fi to mobile handover does not pause the app. (`f2d6c81`, `5217e1c`)
- **Drafts:** Chat, post and comment composers keep unsent text per account in `localStorage`, restored in the first render and cleared on a successful send. A comment that fails after leaving the post is kept to retry. Saves are tied to the account that typed them, so a sign-out or account switch mid-typing never files one person's text under another's. (`05482ad`)
- **Last-seen lists:** Messages, Notifications and Your Communities open on their last first page from the device instead of a skeleton, then refresh in place. Snapshots are per account, always revalidated, and purged at sign-out. The version check runs only after five minutes away. (`82ce045`)
- **Bounded storage:** Caches are capped per store and trimmed at idle. The message cache keeps the newest 300 per chat and never drops unsent or failed rows. Settings gains "Clear cached data", which frees space without signing out or losing unsent messages. (`4b920c1`)

### Events, invites and discussions

- **Create event:** A full-screen page on phones and a centred card on desktop, with a single-day and multi-day toggle and date and time fields that open without shifting layout. The old custom pickers are deleted. (`30ab0bc`)
- **Invites:** Both invite entry points share one sheet that lists followed people and direct chats, with already joined or invited people dimmed. The discussion box stops at 200 characters with a limit message, and Crew gets pull-to-refresh. (`57078e9`)
- **Post images:** The uploader shrinks each post image to a 16 px WebP and sends it with the upload. The API checks its shape, decodes it with `sharp` and stores it in a new `Media.placeholder` column. The feed paints it under a light blur until the real image fades in. GIFs are skipped. (`98ccab1`)
- **Small changes:** The comments skeleton follows the current comment row, and the community Joined button drops its tick. (`cf00e0e`, `1acda57`)

### Performance

- **Redundant indexes:** Seven indexes on Message and ConversationParticipant were exact leading prefixes of a longer index, so they only added work to each message insert and membership write. A migration drops them. (`365525d`)
- **Unused index:** Production statistics from 25 August to 22 October show zero scans of one Notification index against 790 for its twin. Dropping it saves a write on every notification insert. (`010302d`)
- **Activity discussion paging:** Each page checks access, looks up its cursor and reads the block list together, and message rows are memoised so typing no longer re-renders the history. (`4905d2b`)

### Security

- **No Android backup:** Every account's data lives on the server, while a backup copied cached message bodies, the profile and feed off the phone. `allowBackup` is false, and the extraction rules exclude every domain from cloud backup and device transfer. It takes effect from the next APK release. (`aa69295`)
- **Dependencies:** `nodemailer` moves from 9.1.1 to 10.2.1, clearing five advisories including an address-parser backtracking and a TLS servername leak. The only breaking change is Node 20 or newer, and the image runs Node 22. `sanitize-html` moves to 2.18.1. `npm audit` for production dependencies reports nothing. (`9813e74`)

## Fixes

### Lost data

- **Notifications paging:** The cursor pointed at the look-ahead row, so the next page skipped it and one notification vanished at every page boundary. It points at the last row returned, with an id tiebreak. Join-request alerts reached an arbitrary 25 reviewers and now notify all, up to a logged ceiling. (`1cf61a4`)
- **Duplicate posts and comments:** A post, its media and its poll now commit in one transaction, and media is attached by one `UPDATE` that only takes the author's own, still unattached uploads, so two posts cannot claim one image. Each effect after a comment commits runs on its own. A response too large to replay keeps its key with a done marker, and a repeat gets 409 `IDEMPOTENCY_ALREADY_PROCESSED` instead of a rerun. (`a49ca13`)
- **Notification dot:** Opening Notifications marks everything read at once and cancels in-flight unread-count fetches, so a cleared dot cannot come back. (`960aa29`)

### Review fixes

- **Idempotency scope:** Routes that touch the response (sign-in, refresh, adopt, sign-out) are no longer idempotent, because a replay lost the session cookie and the stored body held the app's tokens. Claims expire in 60 s so a crashed request cannot block a draft for a day, the send lock falls back to unlocked when Redis is down, and a deduplicated send notifies nobody again. (`94d2b86`)
- **Claim ownership:** Claims carry a token so only the owner may release, complete or extend them, and the still-processing 409 says `IDEMPOTENCY_IN_PROGRESS`. (`7042832`)
- **Query strings:** A reused key on a route that reads its input from the query string is refused instead of replaying another request's result. Catch-up checks Instant Match access ten at a time, and the production env example records the measured proxy hop count of 2. (`26d27ee`)
- **Outbox edge cases:** Unsent and failed messages reappear after a restart, and a sign-out mid-send can no longer write or send as the previous account. An unreadable outbox is retried instead of read as empty, an unsaved message cannot overtake an older one, and a failed feed refresh restores its pages. Blocked database upgrades no longer hang, and a different account after an unverified launch gets a full purge. (`228f25a`, `b9208b7`)
- **Cache isolation:** A late response can no longer write a signed-out account back into IndexedDB, and a session that ended while closed is purged at boot. The service worker no longer caches signed-in API JSON. (`9d69271`)

### Create-event form on Android

The page was shrunk by the keyboard in one frame and then slid again by the shared sheet, so it moved twice. It stays full height and only its action bar rises. The edge-to-edge layout was lost to a skipped rule. The keyboard covers the Publish button, and the form gains the keyboard's height minus the bar's as room under its last field, appearing in the same frame the keyboard starts opening so a tapped field is revealed. The phone date and time pickers use the same custom calendar and slot list as the design, and the time box is read-only on touch. (`d93bb0f`, `0f2c214`, `70fab49`, `cccf78d`, `eeec9b4`)

### Other fixes

- Reset-password shows a short different-password warning under the field, and the white ID-card guide frame is removed from the verification camera. (`960aa29`)
- Sheets slide with the keyboard. Long-pressing a link or image in the installed app no longer draws the browser's link box. (`9d251b7`)
- Community presence is no longer broadcast over sockets, since the screen no longer shows an active-members count. The HTTP `onlineCount` stays for older apps. (`07c050e`)

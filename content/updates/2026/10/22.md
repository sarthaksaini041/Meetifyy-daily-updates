## Improvements

### Messages that always land

- **Outbox:** every send is recorded in an IndexedDB outbox before it goes out and cleared once confirmed, so a send cut off by the network or a killed app is resent on the next connect, in order per chat, with the same client id the server dedupes. Retries back off to 5 minutes and stop after 8 tries or a day, and refusals are never retried. Entries belong to one account and are wiped at sign-out. (`730487e`) The chat screen no longer sends on the socket itself, so the outbox is the only way a message is sent. It tries the socket, then REST, wakes on reconnect, coming online and resume, and puts a 45 second watchdog on each send. (`27492f5`)
- **Ack codes:** a failed send acknowledgement now says whether a retry can succeed: `REJECTED` for a refusal that never will (blocked, closed chat, not a member, invalid payload), `RATE_LIMITED`, or `ERROR` for anything transient. The outbox retries only the last two, and older builds ignore the field. (`a443676`)
- **Catch-up:** message catch-up pages by time and id with a `hasMore` flag and a server-clock sync point, and honours cleared, left and Instant Match chats. REST sends now dedupe on the client message id, and all send paths lock per client id. (`df86666`) On the client, catch-up pages until done and never advances on error. (`9d69271`)
- **Database dedupe:** the database now refuses a second copy of a client message with a unique index, and the losing insert is answered by finding the winning row and returning it as already delivered. Production held no duplicate pairs. (`6bb60de`)

### Idempotent writes

Writes carrying an `Idempotency-Key` run once per user and route, so a repeat gets the first result and a different body is refused. (`df86666`) Over the day this was narrowed and hardened:

- Sign-in, refresh, adopt and sign-out are never idempotent, because a replay lost the session cookie and the stored body held the app's tokens. Claims expire in 60 seconds, and a send survives a Redis outage. (`94d2b86`)
- Only create forms send a key, so likes and reads add nothing to Redis, and community and activity retries reuse their upload and a whole-minute start. (`bfe4697`)
- Only the nine create routes that clients key per submission accept a key, results live an hour and are capped at 32 KB, because Redis runs without eviction. A client id reused in another chat is refused. (`e2f62a4`)
- A reused key on a route that reads its input from the query string is now refused. (`26d27ee`)
- A retry of a delivered message returns it before any block or membership check, and claims carry a token so only their owner may release or extend them. (`7042832`)
- A post, its media and its poll commit in one transaction, and media is attached only to the author's own, still unattached uploads, so two posts cannot claim one image. A retried create can no longer make the post or comment twice. (`a49ca13`)

### Offline and on-device storage

- One network signal drives the app's data layer and a single offline and back-online notice. Creates are refused offline with the draft kept, toggles are refused instead of flipped and undone, and screens keep cached data through failed refreshes. (`f2d6c81`)
- On Android the app reads connectivity from the system. A network not yet validated counts as online, and a drop is re-checked after 500 ms so a Wi-Fi to mobile handover does not pause the app. (`5217e1c`)
- Messages, Notifications and Your Communities open on their last first page from the device instead of a skeleton and then refresh in place. Snapshots are per account and purged at sign-out. The version check only runs after five minutes away. (`82ce045`)
- Caches are capped per store and trimmed at idle, the message cache keeps the newest 300 per chat and never drops unsent or failed rows, and Settings gains "Clear cached data". (`4b920c1`)
- Half-typed messages, posts and comments are kept as drafts per account and restored on the first render. (`05482ad`)
- A late response can no longer write a signed-out account back into IndexedDB, a session that ended while closed is purged at boot, and the worker no longer caches signed-in API JSON. (`9d69271`)
- Unsent and failed messages reappear after a restart and a refused send shows "Not delivered" with a working retry. Both IndexedDB caches share one clear. (`228f25a`, `b9208b7`)

### Campus events, invites and discussions

- **Create event:** a full-screen page on phones and a centred card on desktop, with a single-day or multi-day toggle and new date and time fields that open without shifting the layout. (`30ab0bc`) Phones show the same calendar and time list as everywhere else, and the time box is read-only on touch so tapping it does not raise a keyboard. (`0f2c214`)
- **Invites:** one invite sheet, built on the share modal's frame and listing followed people and direct chats, replaces the old invite modals. The discussion box stops at 200 characters with a limit message. (`57078e9`)
- **Discussion paging:** each page checks access, looks up its cursor and reads the block list together, and message rows are memoised so typing no longer re-renders the history. (`4905d2b`)
- **Notifications dot:** opening Notifications marks everything read at once so a cleared dot cannot come back, and the bell and Invitations tab show a dot instead of a number. The reset-password page shows a short different-password warning under the field instead of a clipped toast. (`960aa29`)
- Smaller changes: the Joined button on the community page is plain text without the tick (`1acda57`), and the comments skeleton follows the current comment row. (`cf00e0e`)

### Blurred image previews

The uploader shrinks each post image to a 16 px WebP and sends it with the upload. The API checks and decodes it before storing it in a new `Media.placeholder` column, and the feed paints it under a light blur until the real image loads. (`98ccab1`)

### Keyboard

Sheets that make room for the keyboard by layout now slide with it, and moving focus between fields with the keyboard open scrolls the new field into view. (`9d251b7`) On the create-event page, the keyboard now moves the form once (`d93bb0f`), the page fills the screen and the keyboard covers Publish instead of lifting it (`70fab49`), the form ends just above the keyboard with no empty band (`cccf78d`), and the room under the last field appears at once so a tapped field is revealed. (`eeec9b4`)

## Fixes

- **Notifications paging:** the cursor pointed at the look-ahead row, so one notification vanished at every page boundary. It now points at the last row returned. Join-request alerts reached an arbitrary 25 reviewers, and now notify all of them up to a logged ceiling. (`1cf61a4`)
- **No Android backup:** the app no longer allows backup or device transfer, because every account's data lives on the server and a backup only copied private data such as cached message bodies off the phone. (`aa69295`)

## Build & Tooling

- Seven database indexes that duplicate the start of a longer index are dropped, because they only added work to every message insert and membership write. (`365525d`) A notification index with zero scans in production statistics is dropped too. (`010302d`)
- `nodemailer` moves to 10.2.1 and `sanitize-html` to 2.18.1 past their advisories, and `npm audit` for production dependencies now reports nothing. (`9813e74`)
- Community presence is no longer broadcast over sockets, since the communities screen no longer shows an active-members count. (`07c050e`)

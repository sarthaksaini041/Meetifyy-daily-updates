## Fixes

### Jobs crashed on a closed database

Prisma disconnected in the first shutdown pass while BullMQ closed its workers in the last, so on every restart and rollout jobs ran against a closed database and crashed far from the cause. Processors now close their worker in `beforeApplicationShutdown`, and Prisma disconnects in `onApplicationShutdown`. The retry middleware moves to its own file: a query after close throws `DatabaseUnavailableError` instead of returning `undefined`, and pooler refusals and dropped connections are retried twice. (`29777cc`)

### Admin sessions replaced each other

Both admin consoles set `admin_access`, `admin_refresh` and `admin_csrf` on the shared `.meetifyy.app`, so signing in to one replaced the other's session. The names follow `COOKIE_NAME_PREFIX`: production keeps the bare names, so live admin sessions are untouched, and development uses `mf_dev_admin_*`. The guards, refresh and CSRF checks, and the admin frontend read the same names. Dev admins sign in once after this deploys. (`0ac3b0b`)

### Version check and Cloudflare Access

- **First fix:** Ad blockers block `*.ingest.sentry.io`, so on the dev site every event failed with `ERR_BLOCKED_BY_CLIENT`. The website now sends to `/api/app-events` on its own origin, and a host-conditional rewrite forwards it to that environment's own Sentry project. The `/version.json` check uses `redirect: 'manual'`, so an expired Access session reloads once instead of logging a CSP report, a CORS error and `ERR_FAILED`. (`abdb8dc`)
- **Real cause:** The launch check fetched `/version.json` with `credentials: 'omit'`, so on the development site Access never saw its session cookie and redirected every check to its login, signed in or not. It now sends same-origin credentials, checked live to return 200 with the version, and the reload-once path is left for a session that has really expired. (`543d9cb`)

### Crashes reported by Sentry from the app

- The opening screen's drag asked for pointer capture after the pointer had been released, which throws `NotFoundError` and broke the gesture. The call is guarded.
- The `|| []` fallbacks in `useUsersMap` let a non-array value through and Profile crashed on `forEach`. User and conversation lists now go through `asList`.

(`f4cf0bb`)

### Other fixes

- **Push icon:** Notifications showed a generic bell. The small icon is the Meetifyy M traced as a white, alpha-only vector, which is what Android requires, and the FCM payload sends the brand blue as the colour. The icon's name is a contract recorded in `docs/push-notifications.md`. (`6c6aa27`)
- **Splash logo:** The mark on the launch splash is scaled to 0.68, roughly a quarter of the screen width on the test phone. (`d1eb58e`)
- **Settings from Profile:** Choosing Settings closed the menu on the tap, which raced the page transition's screenshot, so the menu vanished, came back and left again. It closes with the navigation, and on a phone each Settings panel slides in like any other screen. (`09ee07b`)
- **Instant Match loader:** The spinner is 40 px and the Find my match button stays hidden until the list has loaded. (`ecc4008`)

## Improvements

### Sentry noise

- **Local runs:** Most of the development projects' noise came from a laptop: API runs with no release, and pages served by Vite's dev server, whose hot-reload errors cannot happen in a build. Outside production the API skips Sentry when it has no `GIT_COMMIT_SHA` unless `SENTRY_REPORT_LOCAL` is true, and the website and app skip it under the dev server unless `VITE_SENTRY_REPORT_DEV_SERVER` is true. Builds and debug APKs are unaffected. (`ea458f1`)
- **Keep-alive pings:** The pool warm-up and the 25-second keep-alive each became a root transaction and were filed as a Slow DB Query issue. Both run through one helper under `suppressTracing`. Checked with the real SDK: two pings recorded 4 root transactions before and none after. (`e4289fe`)
- **pg spans:** Prisma's engine calls the pg adapter from native code, so on Node 22 every query's pg spans inherited the boot trace's context and, once that trace was sent, each went out as its own root transaction, 1,670 in the first 200 seconds of the last dev revision. The Postgres integration is filtered out, since Prisma's own spans already record each statement under the right parent. (`f5e261d`)
- **Units of work:** Work outside a request had no trace to join, so each Redis command or query became one: BullMQ polling (about 121k spans in ten hours of the dev API) and the 10 s Instant Match sweep (about 150k). A `tracesSampler` never starts a trace for a database, cache or middleware span and samples the sweep at 1%. (`e159c63`)
- **Named units:** Timers are `task <name>`, every socket event is `ws <event>` (heartbeat and typing 1%, receipts 5%, ping untraced), plus connects, disconnects and the two domain events that do I/O. Acks, replies and errors are unchanged. (`f5932c7`)
- **Figures:** The quoted volumes came from `count()`, which extrapolates by the sample rate. At 20% they are estimates, and Sentry stored about a fifth. The sweep is compared with the roughly 1,700 traces a day it sent at 20%, not 8,640. (`6c3d8ae`)

### Startup and chats

- **Splash:** It used to stay up until the page said ready, then sat through the platform's own reveal, and flickered at the hand-over. It now hands over at once, keeps its view until the page is ready and painted, then fades out. The Sentry SDK leaves the entry chunk and starts when the first screen is idle. Cold start to a visible Home measured 3.77 s before and 3.47 s after. (`2aa92cd`)
- **Chats open loaded:** Opening a chat started its history request only once the slide began, so the page slid in as a skeleton. A row's first page is fetched on the press, and in the app the top three conversations are fetched once the list is idle, not offline, not on Save-Data and not while a chat is open. (`aa05d3a`)

### UI

- Confirm dialogs for removing a college email, clearing cached data and unblocking open centred on phones, with no drag handle. (`5954284`)
- Communities, search and unverified Campus sit on plain white in light theme on phones, through a shared `useWhiteSurface` hook. (`b532a4c`)
- Every search result wears the same card shell: a thin border, whole-card hover and no tap flash on phones. (`7d1c969`)

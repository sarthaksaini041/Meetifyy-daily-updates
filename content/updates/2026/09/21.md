## Improvements

### The website, wrapped as the native app

- The native build now mounts the real app, with the same routes and screens as the website, instead of a separately rebuilt mobile app. Only the opening screen, the service worker, the version gate, analytics and the API origin differ. CI guards now check that the landing page ships only on the web. (`598a447`)
- Installed Capacitor 8.5.2 and committed the Android and iOS projects. `cap sync` succeeds. (`2d02b1a`)
- Added `build:mobile:dev`, so a debug APK no longer bakes in the production API origin. (`112446e`)
- Branded the launcher icon from the Meetifyy mark and added scripted builds for both APK variants, plus a dev launcher on port 3001. (`6050489`)

### Session-bound tokens for the app

- Backend: the app cannot use cookies, so an access token sent with `x-session-id` now runs the same session checks a cookie runs. A bare bearer token is still refused. Tokens are returned only to the native origin, and `https://localhost` is allowed by CORS. (`26275e1`)
- Frontend: the refresh token and session id are stored in the Keychain / Keystore. The access token stays in memory only and is sent with `x-session-id` on every request. (`73c976f`)

### Native behaviour

- Android's back button is now handled: it goes back when the WebView has history and exits at the root. iOS now uses the `https` scheme, so there is one origin to allow-list. (`76b4c0b`)
- Launch sequence: fixed the black splash handover and the pale flash, regenerated the maskable icons, and added `GET /api/app/version`. That is a fail-open version gate with separate minimum and latest thresholds. (`6801d9f`)
- The status and navigation bars are painted from the app's own theme through a small `SystemUiPlugin`, and the launcher icon is themed. (`a8b6521`)
- The theme follows the device by default, and the auth and legal pages got a designed dark mode. (`c480509`)
- Pure white / pure black chrome for the navigation and system bars, via a new `--color-nav-surface` token. (`2445456`)
- Regenerated the adaptive and maskable app icons from a transparent mark. (`e68fa1b`)
- The native splash screen and system bars are initialized from the persisted app theme. (`04cbe5d`)

## Fixes

### Returning users signed out, and a black launch screen

Three client causes made the app sign returning users out, including a retry that replayed stale headers. Three native theme causes produced the black screen. The splash now holds until the WebView draws its first frame. (`4b5274f`)

### Session lost after an app restart

On a cold start the first request carries no `Authorization` header. The refresh succeeded, but the retry went out still without credentials and reported a valid stored session as dead. The retry now adds the header based on the client, not the original request. (`d3b054e`)

### `gradlew` not executable on a fresh checkout

`gradlew` was committed as 100644. It is now executable in git, and `build-apk.mjs` also runs `chmod` before spawning it. (`1210a9b`)

## Findings

- The first on-device run was on a vivo I2208 (Android 14). Login succeeds, then Chrome blocks every session cookie with `SchemefulSameSiteStrict` because `https://localhost` and the API are different sites. One back press also killed the app. (`5cd64be`)
- Allowing bearer tokens broadly would reopen the revocation bypass closed on 20 September. The sound design is a credential that names its session, which is what was then built. (`eedc42b`)

## Testing

- The frontend suite grew from 1,440 to 1,520 tests over the day, with lint and typecheck clean throughout.
- 12 backend cases cover session-bound tokens and confirm that revoked, expired, unowned, missing and empty session ids are still refused. (`26275e1`)
- The cold-start restart is reproduced by a test that fails without the fix, and was verified end to end against the deployed dev API. (`d3b054e`)

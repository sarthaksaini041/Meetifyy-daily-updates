## Fixes

### Chat media blank in the installed app

Conversation attachments whose media row was missing or still marked public fell into a shortcut that returned a relative `/api/media/<key>` path. That works on the website with a cookie but not in the app. Conversation keys are now always signed, and `useSignedMediaSrc` gives images and video a single entry point with a `pending` state. (`11e3dd3`)

### Media viewer error state and gestures

The WebView's own play-button placeholder showed through the error state. Retry re-requested an expired URL. The error card blocked swipe-to-dismiss, and double-tap still fired on it. All four are fixed. (`5ed4f60`)

### Auth panel re-measuring on every render

A layout effect with no dependency array measured the panel after every commit. It now measures once, then relies on a `ResizeObserver`. The ambient blobs dropped a 64 px `filter: blur` in favour of gradient stops. On the device, jank went from 19.06% to 2.31% of frames, and the 90th-percentile frame from 73 ms to 25 ms. (`12e9d7f`)

### Other fixes

- Legal pages: document body text was hard-coded dark grey and unreadable in dark mode. Pages also flashed a skeleton on every back press; a module-level cache and a layout effect fix that. (`8689539`)
- System-bar icon colour now reads the RGB half of an eight-digit `#AARRGGBB` colour instead of treating the alpha pair as red. (`a1be7e2`)
- Both dev servers were scanning each other's build output for entries and sharing one dependency cache. Each now names its one entry and has its own cache. (`7d9d564`)
- Fixed the profile button styling in the header dropdown menu. (`acd8b27`)

## Improvements

### The app's opening screen

- The mobile dev server now serves the app entry (`index.mobile.html`), so the opening screen can be worked on without building an APK. (`faa2637`)
- Rebuilt the opening screen as one composition: the brand shape, the mascot and two entry buttons. It uses one sizing rule instead of breakpoints and CSS-only motion. The mascot asset went from 228 KB to 56 KB. (`5317968`)

### One shared dropdown menu

- Added `@shared/components/ui/Menu`. It is always portalled to `<body>`, positioned in viewport coordinates, and dismissed on `pointerdown`. (`69a364f`)
- Migrated all fifteen action menus onto it and removed the three separate abstractions that had grown up around the old ones (+612 / −1,309). (`6970bac`)

### Native feel and navigation

- The app hides scrollbars and the long-press text selection, with form fields exempt. (`a8c4f6e`)
- Pull-to-refresh is now a reusable gesture, gated to the app build instead of by viewport width, and applied to home, notifications, profile and the messages inbox. (`a83877f`)
- Inactive icons are full contrast, and whole-screen surfaces are pure black on phones in dark mode, through a new `--color-surface-screen` token. (`608ee59`)
- Navigation icons and text are pure black / pure white. (`d62c99c`) Bottom-bar icon sizes are unified, with no border or shadow. (`e9f9e11`)
- Removed the filter chips from the messages sidebar. (`5371895`)
- The notification bell's filled state is blue, with no border highlight. (`bd61522`)
- Chat headers, details and the sidebar are pure black on mobile in dark mode. (`de32f39`)

### Loading states

- The global loading spinner is standardized, with responsive scaling. (`bd8347f`)
- The notifications skeleton is replaced with a minimal spinner-only loader. (`de936d7`)

## Testing

- The auth flow was measured on the test device across login → signup → login → forgot → login: 58–62 fps throughout, with zero long tasks. (`12e9d7f`)
- The web bundle was verified to contain no pull-to-refresh code, while the mobile bundle carries it. (`a83877f`)
- The full suite passes (1,522 tests), and both dev servers start together without re-optimising. (`7d9d564`)

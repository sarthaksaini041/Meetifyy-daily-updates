## Fixes

### Signed-in users shown the landing page after a reload

Signing in worked, then the next reload showed the landing page. Four separate causes were fixed together (`95635c3`):

- **Provider refresh token exposed to the browser.** Login returned both Supabase tokens so the page could install them, which put the long-lived refresh token in JavaScript and in two hands. Whichever side refreshed first retired the other's copy and tripped reuse detection. Login now returns no token; the server is the only holder.
- **Nothing renewed the cookie session.** `/api/auth/session/refresh` had no callers, so the access cookie simply expired. A 401 now rotates through the server and replays the request once, single-flight.
- **Session restore depended on an unreadable cookie.** The boot probe posted to a CSRF-protected route, which needed `mf_csrf` from `document.cookie`. That is impossible when the API is on another host. It is replaced by a safe `GET /api/auth/session`.
- **Signing out never reached the server.** Logout now revokes the session server-side, keyed on the refresh cookie, so it works even when the access token has already expired.

The launch screen now stays up until the session is actually known. Auth state is an explicit `initializing → authenticated | unauthenticated` sequence, so the router is never told "nobody is signed in" while the cookie probe is still running. A 450 ms minimum stops the logo from flickering on fast boots. Three authenticated cold boots ended on `/home` without ever rendering the landing page. (`0c35e5e`)

### Successful sign-ins reported as failures

Login made a second request to confirm the session and treated any failure of that request as a failed sign-in, which happened on slow mobile data. The login response now carries the full profile, so one round trip answers both questions. Internal messages such as "Supabase is not configured." no longer reach the sign-in form. (`c6f3c7e`)

### Rate limiter rejecting ordinary page loads

`global.ip.burst` allowed 25 requests per 10 seconds per IP. One page load fans out to the feed, communities, notifications, presence and matching, and a campus shares one NAT address, so the limit was raised to 100. `auth.session.refresh` now fails open on a Redis outage instead of signing everyone out, and `auth.session.adopt` was added for the signup handover. (`36ab288`)

### Bearer tokens bypassing session revocation

A bearer caller named no session, so "sign out this device", "sign out everywhere" and password-change revocation were all skipped for it: a lifted access token stayed usable for its full hour. Bearer is now refused unless a route opts in with `@AllowBearerToken`, and only the two signup-handover routes do. The realtime gateway had the same exemption and now requires every handshake to name a live session. (`c32d87d`)

### Session cookies sent to Sentry

Sentry filters cookies by name, and `mf_access` / `mf_refresh` matched none of its sensitive substrings, so both credentials went out verbatim on sampled traces. Cookie collection and stack-frame local variables are now off, and every data-collection field is set explicitly. (`7267368`)

### Chat attachments returning 404

Moving the `chat/`, `messages/` and `voice/` prefixes to the private bucket changed where new objects are written, but reads still looked only there. Reads now resolve the bucket that actually holds the key and cache the answer. Authorized attachments are served through short-lived signed URLs, and video thumbnails, which had never worked, are fixed. Objects written before the move remain in the public main bucket until an operator migrates them. (`19ccac6`)

### Other session and deployment fixes

- The expired-session sweep `purgeExpired()` existed and was tested but never scheduled; it now runs. Only rows past `expiresAt` are removed, so revoked tokens still register as replays. (`98c5fd2`)
- Set `COOKIE_DOMAIN`, `COOKIE_SECURE` and `SameSite` on the dev container app to mirror production. The live app now emits `Domain=.meetifyy.app; Secure; SameSite=Strict`. (`63d957e`)
- Redis `rediss:` connections no longer pass `rejectUnauthorized: false`. The server certificate is verified at all three connection sites, with `servername` set explicitly. (`21395cb`)
- Moved `@nestjs/cli` out of production dependencies. `npm audit --omit=dev` now reports zero backend vulnerabilities (previously one high, via js-yaml). (`02ddf70`)

### Shared messages missing from the sender's own chat

Messages sent through Share Post, Community, Profile or Activity go over HTTP, and that path never passed `senderId`. The sender's other devices were never told about the message. (`2b2936c`) On the client, three further bugs hid them: a cold cache was dropped, writes went to a key nothing read, and optimistic and confirmed copies duplicated. These were fixed with `writeMessageToCaches` and `clientId` idempotency. (`574953e`)

## Improvements

### Mobile navigation drawer and header

- Rebuilt the mobile drawer on the design tokens. It went from seven font sizes to four and from four radii to two, uses a 4 px spacing rhythm and has 44 px tap targets throughout. A profile card now holds the identity and counts, and the overlay blur is halved. (`1c39622`)
- The notification bell got the same 42 px button frame as the other header controls, and the search page now autofocuses its input when opened from the header. (`db2273d`)
- Unified the communities box across the sidebar and the mobile drawer into one `CommunitiesBox` component, made the post preview height dynamic, and removed the settings subtitles. (`c25bd28`)

### Chat previews

- Adapted post and reply previews for polls and media with a new `PostReplyPreview` component and tests, and fixed the poll icon orientation. (`ee816cf`)
- Rounded reply-preview corners and tightened the conversation list, then reverted that change. (`9d9c409`, reverted in `95a9439`)
- Tightened the conversation list item margin and the filter row padding on mobile. (`0932876`)

### A portable frontend core

The frontend was split so a second client can share it:

- Removed 20 unused resolve aliases. (`849c86b`)
- Added the `core/` and `platform/` scaffolding with lint-enforced boundaries. (`d743715`)
- Moved the 20 API endpoint namespaces into `core/`, unchanged. (`c8233a9`)
- Put the API origin behind a platform seam. This fixes a WebView resolving the backend to `localhost`. (`b785b09`)
- Decoupled the transport from the browser and from Supabase. (`68923e7`)
- Enforced the boundaries in CI and deleted two dead stores. (`a45fe7c`)
- Moved the HTTP transport into `core/` as a factory. `apiClient.js` went from 1,639 to 155 lines. (`4b4fb5b`)

On top of that, a mobile build target now compiles from `core/` over `platform/capacitor/`, with no service worker and a 1.82 MB bundle against the website's 4.6 MB. The web build is byte-identical. (`e9480ef`) A preview script serves the mobile bundle locally (`afaff96`), and the mobile config now sets `base` explicitly. (`844c2a5`)

## Findings

- The React Query cache was never cleared on sign-out. The next person on a shared machine could be shown the previous user's feed, messages and profile from memory. `resetClientStateForNewUser` now clears it. (`a45fe7c`)
- `directBackendUrl()` and `getMediaUrl()` both derived the API origin from `window.location`. Inside a Capacitor WebView that would have pointed every request and private media URL at `localhost`. (`b785b09`)

## Testing

- The suite grew from 124 test files / 1,296 tests to 133 / 1,440 over the day. Lint, the boundary rules and the contract typecheck pass at each step.
- The boundary rules were proven with a deliberate probe (10 errors from 10 violations), and the new sign-out cache guard fails 3 of 4 cases without the fix. (`d743715`, `a45fe7c`)
- The share-delivery test pins the missing-`senderId` case. Its unused React import, the only lint warning in the tree, was removed. (`2b2936c`, `ba8f7d9`)
- Attachments were verified against a live session: image, video and thumbnail load on the fixed build and fail on the old one. (`19ccac6`)

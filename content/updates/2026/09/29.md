## Fixes

### Installed app could not hold a socket connection

- **Session id:** The gateway took the session id only from the `mf_sid` cookie, which a WebView never stores, so every native socket was accepted and then disconnected and Instant Match sat on "Reconnecting". The client now sends `sessionId` in the handshake and the gateway falls back to it, through the same lookup: the session must exist, be live and belong to the user the token names. Builds that send nothing behave as before. (`3ee873c`)
- **Token:** In the installed app the token lives in secure storage, so the connect packet carried a session id but no token and the gateway still rejected it. The handshake now sends `token || getAccessToken()` on every connection, which also stops a reconnect after a token refresh presenting the old token. (`eaa5f59`)

### "Sign out other devices" signed out this device too

`currentSessionId()` read only the `mf_sid` cookie, so for the installed app it was always null. "Sign out other devices" and a password change revoked every session, including the caller's, and the device list marked no current device. It now falls back to `x-session-id`, which `JwtGuard` already resolves and matches to the token's user. A cookie session still wins. Two raw-fetch uploads that sent a bare bearer token now send `x-session-id` as well. (`f5109a1`)

### Shared links opened nowhere in the app

Inside the installed app, `window.location.origin` is the WebView's own `https://localhost`, so shared post and conversation links went nowhere. The app now uses `VITE_SITE_URL`, and the website keeps the page origin. (`ca7e760`)

### Email render scripts

`tsconfig.render.json` turned `strictNullChecks` off, which `strictPropertyInitialization` refuses to coexist with, so `email:test-all` and `render:templates` both failed to compile. (`9fc7267`)

### Splash and profile polish on a real device

- **Static splash:** The breathing animation never ran, because Android 12+ draws a held splash in its own window, and handing the splash over early to animate it once moved the logo about 15 px. The logo is static and the system holds the splash until the app has painted. (`f883800`)
- **Cover layering:** The fixed copy of the profile cover drew over the avatar, and the header shade was a solid band with a hard edge. The cover lives in the page again under the avatar, and the header shows its own clipped copy that scrolls away, pins and blurs. (`0061962`)
- **Header edge and pull:** The soft lower edge of the header band melted the pinned header into the page, and during a pull the blurred layer spilled onto the card below like a shadow. The mask is removed and the layer is clipped. (`85d0d61`)
- **Hairline in a pull:** The header's cover and the page's cover met on fractional pixels, and the row between them let the page show through as a thin white line. The band now extends 4 px over identical pixels. The largest single-row brightness jump in the cover area dropped from 20.5 to 6.5, which is photo texture. (`5c2c316`)

## Improvements

### Profile header

The avatar keeps its size until its top edge touches the header, then shrinks and fades beneath it and grows back on the way up. The name and handle fade as they pass under the header, and the header title fades in on the name's own view timeline so the two hand over frame for frame. All three run as CSS view timelines. (`1b05ca7`)

### System bars painted from the page

The bars are transparent and the WebView runs beneath them. The page paints them in the same animation frame as the change that caused it, so they no longer lag a navigation by 70 to 500 ms. Native only sets icon appearance, the window colour, the theme for the next launch and publishes insets. A `useSystemBars` hook serves full-bleed screens, and the drawer, viewers, Create Activity and Activity Detail clear the bars. (`d71e8bc`)

### Share sheet

One `ShareSheet` replaces the four share dialogs: a drag-to-dismiss sheet with a multi-select recipient grid and a single Send, and the external share row with Copy link first. Chat payloads are built in one place and keep the exact shapes the chat previews of installed apps already read. Instagram Stories is native and app-only, and links open in the app through Android App Links. (`02ad0fb`)

### Reply bar

The reply composer on a post is replaced by a floating bar docked above the keyboard and navigation bar, with an avatar and "Post your reply...", and a Send button once there is text. (`bce746e`)

### Skeletons instead of placeholders

Empty states no longer show while content is loading on profile posts, community posts, campus suggestions, the directory and campus communities. Skeletons keep headers, titles, tabs and buttons real and draw only the major content blocks. Chat threads, notifications, devices, verification status and invite lists use skeletons instead of spinners. (`ad47162`)

### Transactional emails

All ten emails get a new composition: a centred wordmark, sentence-case labels, a bold headline, hairline-ruled detail lists, tinted callouts and a light panel with one bordered box per digit for one-time codes. System fonts only, because web fonts render in Apple Mail alone. Props, defaults, copy and conditionals are unchanged. The account-deletion email now puts its warning before the code, as its doc comment intends. (`632b451`)

### Debug build label

The debug (development) build is labelled "Meetifyy DEV". Only the debug resource changes, not the release variant or the application id. (`2c602e5`)

### Performance

- **Cold-start sign-in:** The installed app keeps its access token in memory only, so every cold start sent the session probe into a guaranteed 401, then refreshed, then replayed: three serial round trips under the splash. It now renews up front when a refresh token is held and no access token, on the same single-flight promise. A 401 for a request whose token was already replaced replays with the new token instead of rotating again. (`9224bff`)
- **Splash release:** The page pushes readiness to native at release, because the polling call queued behind the busy main thread and saw it about 500 ms late. The poll stays as the fallback, with a timer backstop independent of `requestAnimationFrame`. A returning user's home route chunk and first feed page start alongside the session restore. (`d8cdd68`)
- **Entry chunk:** `framer-motion` and `socket.io` leave the entry chunk. The public 404 is lazy, `socket.io-client` loads on first connect with a guard against a disconnect during the load, route preloads run one per idle period, and mention search, recent searches and the header's own-profile fetch wait until needed. (`a2db26f`)
- **Profile cover:** The blur is a canvas of about 48 px drawn once and stretched by the GPU, replacing two full-size CSS `filter: blur()` layers, and the scroll share is a compositor-driven scroll animation. Measured on a device over three cold runs, counting frames over 20 ms. (`241e45a`)
- **Pull to refresh:** The pulled distance was React state, so every `touchmove` re-rendered the wrapper. It now lives in a ref and is painted to the DOM once per animation frame. React state changes only with the phase. (`387af7c`)
- **Covers:** Covers are fetched and decoded before the screen needs them. Your own cover is warmed in idle time, others when their profile is fetched, and the installed app cuts to the photo instead of cross-fading. (`0545483`)

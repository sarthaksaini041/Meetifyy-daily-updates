## Fixes

### Signup session handover and OTP submission

In the app (Capacitor APK), the verified session was not always handed to the app's session layer. Profile and session requests could then reach the backend with no authorization token. The verified session is now handed over explicitly, and the code is submitted once, so duplicate OTP submissions no longer happen. (`51816ac`)

### Adopted session dropped after signup

Calling `signOut({ scope: 'local' })` after adopting the session could invalidate the provider session that had just been adopted. It is replaced with in-memory state cleanup, so the session stays alive. The welcome email is now sent reliably after account setup. (`beeac10`)

### Profile created before the session that references it

The backend tried to create a session before making sure the app profile existed. For accounts where verification succeeded but profile creation had failed earlier, this caused foreign-key failures. The order is now: profile sync → validation → session creation → notification. Login notifications are no longer sent before a session exists. (`b0755c2`)

### Session cookies shared between environments

Development and production used the same session cookie names under `.meetifyy.app`, so one environment could overwrite or reuse the other's session. Each environment now has its own cookie names, and production keeps its existing names. (`89e33e6`) Stale host-only cookies from older deployments could also override the newer domain cookies. They are now expired whenever a session is issued or cleared. (`70cf95d`)

### CORS open across environments

The broad `https://*.meetifyy.app` pattern is replaced with explicit origins per environment:

- Development and production frontend and admin origins are separate.
- Credentialed requests can no longer cross environments.
- Unsafe origin patterns are rejected at validation.
- The Capacitor app origin is included.

(`e1f13a2`)

### Stale CSP hashes

CSP hashes were generated before the final prerendered HTML existed, so they went stale. Now:

- Inline scripts stay the same between builds.
- The build ID lives in a separate `meetifyy-build` meta tag.
- Hashes are checked after prerender, on every page, and a wrong or missing hash fails the build.
- Cloudflare's JavaScript Detection script is still handled separately, because it is injected at the edge.

(`3f58667`)

### Settings back button looping on phones

The mobile Settings back button pushed parent routes instead of following history, so it could loop. It now goes back when history exists, falls back to the right parent for deep-linked pages, and uses replace navigation where needed. The desktop split view is unchanged. (`f376741`)

### Other fixes

- Scrolling is locked while the launch shell shows on reload. (`07bec83`)

## Improvements

### Landing page light and dark mode

The landing page forced light mode and fought the global theme system. It now follows the selected or system theme, including themed scrollbars, the signup journey components and the footer. (`15fe5a5`)

### Dark-mode phone surfaces

The remaining full-screen phone surfaces are pure black in dark mode: post view, Settings, drawers, chat settings, and the gallery and group-settings screens. They use the `--color-surface-screen` token instead of scattered overrides. (`330e328`)

### Branding

- The reload loader screen is updated, and the transparent Meetifyy logo now matches the mobile APK splash. (`f29e7de`)

## Findings

### Backend lint audit (in progress)

The backend has 8,000+ lint errors. They are being grouped by rule and root cause, not auto-fixed or suppressed. The plan:

- Fix recurring patterns at their source, and separate mechanical issues from real type-safety or correctness problems.
- Avoid new `eslint-disable` comments.
- Write down coding rules that stop the patterns coming back.
- Add tests where a finding shows a real runtime risk.

This is the next priority. No commits yet.

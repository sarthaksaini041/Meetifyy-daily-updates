## Fixes

- Refreshing or hand-editing `?step=` now lands on the first incomplete signup step. (`20f9306`)
- Going back to the password step with an address a code was already sent to no longer dead-ends on "signup already pending". (`20f9306`)
- Dropdowns in signup and Settings render in a portal fixed to the viewport, flip when needed and match their field's width, so the card or page can no longer clip them. (`20f9306`, `b2ddd87`)

## Improvements

### Six-step signup

Signup is split into short steps, each asking only for things that belong together, in the order the backend needs them:

1. **Say hello**: name and college email (the approved-domain check is unchanged).
2. **Your profile**: username and birthday.
3. **College**: course, branch and year. The college is read from the email.
4. **Password**: password and Terms/Privacy consent, then "Create account".
5. **Verify**: the emailed code, with resend and "Change email".
6. **Photo**: an optional avatar, with "Finish" or "Skip for now".

A finishing screen ("Creating your profile / Wait a moment / Almost done") waits for account completion before moving into the app. It never runs on a timer and runs once only, including under StrictMode. (`20f9306`)

### Auth shell and building blocks

Every auth page now renders through one shared frame:

- **AuthShell**: a card that morphs between pages without text reflowing, a named step rail and header progress bar for signup, story copy that is right on the first frame, prefetching of sibling auth pages, and direction-aware slides with a full-screen layout and top-left back button on phones.
- **AuthAlert**: form-level notices float outside the card, with a title, tinted icon and an optional countdown that pauses on hover.
- **AuthButton**: a spinner slides in while loading, and the button never changes size.
- **AuthField**: error text is linked to the input for screen readers, and a reserved message line stops errors shifting the layout.

Fields are borderless and filled, with thin focus rings, pill buttons, light and dark themes and reduced-motion support. (`62893b0`)

### Login, forgot-password and reset-password pages

- Login uses label-less fields, a "Forgot password?" text button under Log in and a "Create account" button at the foot of the page.
- A plain-language message shows when the server cannot be reached, and the notice re-appears on a repeated failure. The previous error stays put during a retry so the layout does not jump.
- Forgot password reports an invalid address under the field instead of in a toast.
- All three pages share one source for story copy and get the phone back button (reset returns to login).

Authentication logic, requests and redirects are unchanged. (`896c7f0`)

### Settings matches the auth pages

Inputs, birthday and dropdown triggers use the same borderless style and focus ring. Lists have tighter spacing, full-width dividers and no row chevrons. Settings behaviour and content are unchanged. (`b2ddd87`)

### Dark-mode phone screens

The "Account verification required" page and the "Something went wrong" screen are pure black on phones in dark mode, with secondary buttons adjusted to stay visible. (`8e542ae`)

## Testing

- New tests cover alert auto-hide, first-paint story copy, the finishing screen and the pending-code path. Existing email-gate and single-OTP-submit tests were retargeted to the renamed steps. (`62893b0`, `20f9306`)

## Build & Tooling

- A local-only step switcher was added to review the signup flow, then removed once the review was done. Every step again requires the ones before it, and the finishing screen always completes the account for real. (`de2f9d1`, `f7caf2a`)

## Fixes

### Read receipts ignored on `GET /api/messages/:id`

Removing an `as any` exposed a privacy bug. The history route the app calls returned every participant's `lastReadAt` and marked messages `read`, even for users who had turned read receipts off. The participant query never selected `settings.readReceipts`, so the check read `undefined` and always passed. The setting is now selected and those users are ignored, as the DM and group routes already did. A spec that failed on the old code now covers it. (`e22247f`)

### Socket payloads were never validated

The global `ValidationPipe` only runs for HTTP, so a declared `{ conversationId: string }` on a socket event checked nothing, and an object could reach Prisma as a filter. Now:

- Typing, delivered, received, seen and mark-seen events resolve the conversation for the sender as an active participant, with one indexed query cached briefly, and do nothing otherwise.
- Any signed-in user who knew a conversation id could previously send those events into it.

(`c61e75e`)

### Made-up key ids forced a JWKS fetch each time

A token naming an unknown `kid` forces a JWKS refresh, and `force` skipped every throttle. A stream of tokens with invented ids was one outbound request to Supabase per inbound request, and `RateLimitGuard` does the same lookup on every request, so it was reachable without signing in. Every fetch, forced or not, now waits at least 30 seconds after the previous attempt. A real key rotation still heals once that has passed, and the remote fallback covers the gap. (`79cd474`)

### Admin token algorithm and session ownership

All admin tokens are signed and verified with one constant algorithm (HS256). `AdminJwtGuard` accepted HS384/HS512 while the rate limiter verified the same cookie as HS256 only, so they now agree by construction. Existing tokens are HS256 and keep working. The guard and `refreshTokens` also refuse a session that belongs to an admin other than the one the token names. (`e2227f5`)

### First sync returned the raw database row

The sync that creates an account returned the Prisma row it had just written: every column, including purge bookkeeping, and none of `meta` or `isFirstYearStudent`. The client drew a new first-year student as unrestricted until the next sync, although the server still enforced the policy. Account creation now reads the new row back through the same query and builds the same profile as an existing account. (`a98dc04`)

### Audit log rows lost or garbled

- A repeated `x-request-id` header is an array, which the `requestId` column rejects. The insert failure was swallowed and the row never written. It is now stored as null.
- A text body was spread character by character into `newValue`. Only an object body is recorded now.

(`1a9fbc7`)

### Other fixes

- `async` functions that awaited nothing are no longer `async`, with throw timing unchanged on every path. Tested promises are awaited. (`13f6ca8`)
- Malformed email jobs that no producer creates now fail up front with a clear message. (`27cb06c`)
- The image-rendering route tests failed intermittently (`Exceeded timeout of 5000 ms`, then `ECONNRESET`) on a busy machine. The file now has a 30 s render budget, and nothing in it asserts speed. (`7fe01b4`)

## Improvements

### Typed auth, errors and request handling

- **Profile sync:** `syncProfile` returned `any`. It now returns a typed profile, takes only the identity fields it reads, and cookies are read through `readCookie()`, since `cookie-parser` turns `j:` cookies into objects. (`c9e0753`)
- **Error logging:** `redact()` keeps passwords, tokens and OTPs out of the error logs and had no direct test. A spec now pins every sensitive key, case-insensitive matching, nested values and non-mutation, and it passed before and after the typing change. The exception filter reads a typed request, and the error body clients receive is unchanged. (`41dea2c`)
- **Filters:** `injectBlockFilter` returned `T & { AND?: any[] }`, so every caller stored `where: any`. It now returns the caller's own Prisma type, which keeps the compile-time protection for the blocking and isolation rules. (`7e2e5c3`)

### Realtime gateway

- Socket identity (user id, name, session id, conversation ids) moves from 28 `(client as any)` sites to a typed `socket.data`, the documented per-socket store that also survives a Redis adapter. Behaviour is unchanged. (`4676030`)
- Domain-event routing reads Redis JSON through typed readers in the same fallback order as before. A differential test ran the old and new handlers on 30 event shapes. The gateway went from 260 lint violations to none. (`a3bf285`)

### Messaging

- The 48-hour group-invite expiry was written out six times. It is now one helper, checked against the old code on 100 combinations with a frozen clock. (`aa215f3`)
- `MessagingCoreService` (235 violations to none), `MessagesService`, `GroupChatsService`, `DmService` and the messaging controllers are typed end to end. The message create no longer casts its data to `any`, which had switched off inference for `sender` and `replyTo`. (`fbdccba`, `c6fe729`, `ef9e40c`, `6ce1ba4`)
- `POST /api/messages` takes `userIds` through a parser, because `ValidationPipe` does not check array parameters. (`6ce1ba4`)

### Feeds, community and admin services

- **Activities and communities:** `ActivitiesService` goes from 164 violations to none, and `CommunitiesService` no longer mutates loaded rows. (`0d4623c`, `23c2f3e`)
- **Posts:** One `buildPollView()` replaces three copies of the poll block, and search shares it. (`4815007`, `8fbe596`)
- **Users:** The raw SQL queries have row types matching their `SELECT` lists. (`0082adb`)
- **Campus events and admin:** Both services and their filters use Prisma's own types. (`8a4a0d6`, `366ccf2`)

### Infrastructure typing

- Email job data is one shared contract between the queue and the worker, so a renamed field fails at compile time instead of at send time. (`27cb06c`)
- Notification metadata is `Prisma.InputJsonObject` and domain event data is `unknown`. (`5767a75`, `0e0ab40`)
- `PrismaService`, the pino config and the BullMQ connection lose their casts. A 65-case differential of the retry middleware matched on result and call count. (`0b47092`)
- Instant-match payload parsers take `unknown`. A differential over 6,000 generated payloads matched on every result and error message. (`6af338a`)

### New login and signup experience

- The shared auth frame is rebuilt: a card that morphs between pages, a named step rail for signup, story copy keyed by route so the first frame never flashes generic text, prefetching of sibling auth pages, direction-aware slides and a full-screen layout on phones. (`70a43dc`, `62893b0`)
- Login, forgot-password and reset-password are redesigned: label-less fields, a "Create account" button at the foot of login, a plain-language message when the server cannot be reached, and an invalid address reported under the field instead of in a toast. (`896c7f0`, `4a3cd5c`)
- Signup is split into six short steps with a finishing screen: name and college email, username and birthday, course and year, password with Terms consent, emailed code, and finish. The approved-domain check is unchanged. (`20f9306`, `033eb55`)
- A local-only step switcher was added to review the flow, then removed a few minutes later once the review was done. It was dev-server only and never in a production build. (`de2f9d1`, `74c875e`, `3b71327`, `f7caf2a`)
- Settings fields, dropdowns and lists match the auth style. Dropdown menus render in a viewport-fixed portal, so page overflow can no longer clip them. (`b2ddd87`, `0a72fe6`)
- The "Account verification required" and "Something went wrong" screens are pure black on phones in dark mode. (`8e542ae`, `307e25b`)

## Testing

- 524 `async` mock functions in specs that never awaited are rewritten to return promises explicitly, with the transformation chosen per shape so callers see exactly what they did before. (`ceebfe7`)
- A `stub<T>()` helper hands a constructor a partial dependency typed as the real one, so a renamed method fails to compile in the spec instead of leaving a mock nothing calls. The shared mocks use `satisfies`, and 24 casts disappear. (`5637446`)
- The verification e2e, account-deletion purge, activity-access, instant-match, admin legal, privacy and group-invite specs get typed fakes. (`d858507`, `89c2b0e`)
- Two specs rewritten during typing had their assertions changed. They are restored to the original assertions, with only the two new tests added. (`05fb652`)

## Fixes

- Refreshing or hand-editing `?step=` now lands on the first incomplete signup step. (`20f9306`)
- Going back to the password step with an address a code was already sent to no longer dead-ends on "signup already pending". (`20f9306`)
- Dropdowns in signup and Settings render in a portal fixed to the viewport, flip when needed and match their field's width, so the card or page can no longer clip them. (`20f9306`, `b2ddd87`)

### Security and auth

- **Read receipts:** `GET /api/messages/:id` returned every participant's last-read time and marked messages as read even for people who had turned read receipts off, because its query never selected the setting. It now honours it, like the DM and group routes. (`e22247f`)
- **Realtime events:** socket payloads were never validated, and any signed-in user who knew a conversation's id could make typing indicators and delivery or read receipts appear in it and have a read recorded. Typing, delivery and seen events now resolve the sender as an active participant, every payload is parsed before use, and `message:send` is validated like the HTTP route. The unused `presence:get` and `presence:get_status` events are removed. Also, the HTTP fallback for a slow socket ack was rejected with a 400, which showed the message as failed. (`c61e75e`)
- **Fake key ids:** a token naming an unknown key id forced a key-set fetch on every request, so a stream of tokens with invented ids was one outbound request to the identity provider per inbound one. Fetches now wait at least 30 seconds after the previous attempt. In a test, 25 such tokens now cause one fetch instead of 26. (`79cd474`)
- **Admin tokens:** all admin tokens are signed and verified with one fixed algorithm (HS256), and a session that belongs to a different admin than the token names is refused. Existing tokens keep working. (`e2227f5`)
- **First sync of a new account:** the sync that creates an account returned the raw database row, with none of `meta` or `isFirstYearStudent`, so the client drew a new first-year student as unrestricted until the next sync. It now returns the same profile as every later sync. (`a98dc04`)
- **Profile typing:** what the sync returns and what the auth routes read are typed, and cookies are read only as strings. (`c9e0753`)
- **Audit log:** a repeated `x-request-id` header made the audit row fail to insert (and the failure was swallowed), and a text body was spread character by character into the log. Both are fixed. (`1a9fbc7`)
- **Error logging:** the redaction function that keeps passwords, tokens and OTPs out of error logs is typed and its output pinned by a new test. (`41dea2c`)
- **Blocking filters:** the blocking and isolation filters keep their caller's Prisma types, and the Supabase client is auth-only, so a data query through it is now a compile error. (`7e2e5c3`)

### Smaller fixes

- A malformed poll option (an object or array) was stored as `"[object Object]"`. It is now dropped with the blank options. (`4815007`)
- Two malformed email jobs that no producer creates now fail with a clear error and are retried, instead of reaching Prisma or the transport with an undefined value. (`27cb06c`)
- A repeated group-invite expiry rule, written out six times, is one helper. A stored media field that is not a string is reported as null. (`aa215f3`)
- `startConversation` ids are parsed. An id that is not a string is now a 400 instead of a database error (500). (`6ce1ba4`)

## Improvements

### Six-step signup

Signup is split into short steps, each asking only for things that belong together, in the order the backend needs them:

1. **Say hello**: name and college email (the approved-domain check is unchanged).
2. **Your profile**: username and birthday.
3. **College**: course, branch and year. The college is read from the email.
4. **Password**: password and Terms/Privacy consent, then "Create account".
5. **Verify**: the emailed code, with resend and "Change email".
6. **Photo**: an optional avatar, with "Finish" or "Skip for now".

A finishing screen ("Creating your profile / Wait a moment / Almost done") waits for account completion before moving into the app. It never runs on a timer and runs once only, including under StrictMode. (`20f9306`)

### Auth shell and building blocks

Every auth page now renders through one shared frame:

- **AuthShell**: a card that morphs between pages without text reflowing, a named step rail and header progress bar for signup, story copy that is right on the first frame, prefetching of sibling auth pages, and direction-aware slides with a full-screen layout and top-left back button on phones.
- **AuthAlert**: form-level notices float outside the card, with a title, tinted icon and an optional countdown that pauses on hover.
- **AuthButton**: a spinner slides in while loading, and the button never changes size.
- **AuthField**: error text is linked to the input for screen readers, and a reserved message line stops errors shifting the layout.

Fields are borderless and filled, with thin focus rings, pill buttons, light and dark themes and reduced-motion support. (`62893b0`)

### Login, forgot-password and reset-password pages

- Login uses label-less fields, a "Forgot password?" text button under Log in and a "Create account" button at the foot of the page.
- A plain-language message shows when the server cannot be reached, and the notice re-appears on a repeated failure. The previous error stays put during a retry so the layout does not jump.
- Forgot password reports an invalid address under the field instead of in a toast.
- All three pages share one source for story copy and get the phone back button (reset returns to login).

Authentication logic, requests and redirects are unchanged. (`896c7f0`)

### Settings matches the auth pages

Inputs, birthday and dropdown triggers use the same borderless style and focus ring. Lists have tighter spacing, full-width dividers and no row chevrons. Settings behaviour and content are unchanged. (`b2ddd87`)

### Dark-mode phone screens

The "Account verification required" page and the "Something went wrong" screen are pure black on phones in dark mode, with secondary buttons adjusted to stay visible. (`8e542ae`)

## Testing

- New tests cover alert auto-hide, first-paint story copy, the finishing screen and the pending-code path. Existing email-gate and single-OTP-submit tests were retargeted to the renamed steps. (`62893b0`, `20f9306`)
- The two rewritten specs get their original assertions back, after typing replaced one with a stricter check. (`05fb652`)
- The image-rendering route tests get a 30-second render budget. They failed intermittently under load; with the default forced to 800 ms they failed 20 of 48 before and pass 48 of 48 after. (`7fe01b4`)
- 524 `async` mock functions that never awaited now return promises explicitly, with every assertion unchanged. (`ceebfe7`)
- A typed `stub<T>()` helper replaces `as any` for dependencies, and the shared mocks and gateway spec use it. The gateway spec went from 251 lint violations to 0. (`5637446`)
- The verification e2e, account-deletion purge and activity-access specs are typed. (`d858507`)
- The instant-match, admin legal, privacy and group-invite specs are typed. (`89c2b0e`)

## Build & Tooling

- A local-only step switcher was added to review the signup flow, then removed once the review was done. Every step again requires the ones before it, and the finishing screen always completes the account for real. (`de2f9d1`, `f7caf2a`)
- **Realtime:** socket identity lives in a typed `socket.data` (`4676030`), and domain-event routing is typed and dead gateway code removed, taking the gateway from 260 lint violations to 0. (`a3bf285`)
- **Async:** `async` is dropped where nothing is awaited, without changing throw timing. (`13f6ca8`)
- **Messages:** MessagingCoreService (`fbdccba`), MessagesService (`e22247f`), GroupChatsService (`c6fe729`), DmService (`ef9e40c`) and the messaging controllers (`6ce1ba4`) are typed end to end, with dead reads removed.
- **Notifications, email and infra:** notification metadata and domain-event data are typed at the source (`5767a75`), `emit` and presence reads are typed (`0e0ab40`), as are PrismaService, the logger and the queue connection (`0b47092`), and the instant-match and uploads services. (`6af338a`)
- **Feature services:** ActivitiesService and its controllers (`0d4623c`), CommunitiesService (`23c2f3e`), PostsService, with one poll builder for the three read paths (`4815007`), UsersService (`0082adb`), CampusEventsService (`8a4a0d6`), search and the shared modules (`8fbe596`) and the admin list filters and report writes (`366ccf2`).

Most of these were checked with differential tests that ran the old and new code side by side on hundreds of generated inputs and required identical output.
